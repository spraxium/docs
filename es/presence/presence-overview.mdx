## Qué resuelve el sistema de presencia

Los bots de Discord muestran un indicador de estado (online, idle, do not disturb, invisible) y una línea de actividad bajo su nombre (Playing, Watching, Listening, Streaming, Competing). Estos campos de presencia son lo primero que las personas ven al revisar el bot en la lista de miembros. _PresenceManager_ ofrece una API estática para definir y actualizar estos campos desde cualquier parte de tu aplicación, incluyendo soporte para sobrescrituras por shard e interpolación dinámica de placeholders.

Sin un gestor de presencia, tendrías que llamar a `client.user.setPresence()` directamente, lo que implica necesitar una referencia a la instancia del cliente, protegerte contra llamadas antes de que el cliente esté listo y no tener soporte integrado para rotar actividades o mostrar texto específico por shard. _PresenceManager_ maneja todo esto mediante una clase estática centralizada que el framework inicializa automáticamente cuando el bot se conecta.

El sistema de presencia se integra con el sistema de sharding. Cuando tu bot se ejecuta en múltiples shards, cada shard puede mostrar su propio texto de actividad con información específica, como el número de shard o la cantidad de guilds en ese shard. Placeholders integrados como `{{totalServers}}` y `{{shardNumber}}` se resuelven automáticamente a partir del estado en vivo del cliente en cada actualización de presencia.

## Definir una actividad estática

El caso de uso más simple es definir una actividad fija que se mantenga hasta que la cambies. Llama a _PresenceManager.setActivity_ con un nombre y un tipo. El nombre es el texto que aparece en la lista de miembros, y el tipo determina el prefijo que añade Discord (Playing, Watching, Listening, Streaming o Competing).

```typescript filename="src/listeners/ready.listener.ts"
import { Events, Listener, Once } from '@spraxium/common';
import { PresenceManager } from '@spraxium/core';

@Listener(Events.ClientReady)
export class ReadyListener {
  @Once()
  onReady(): void {
    PresenceManager.setActivity({
      name: 'your commands',
      type: 'Listening',
    });
  }
}
```

El método _setActivity_ solo cambia la actividad. No toca el indicador de estado. Si quieres cambiar ambos a la vez, usa _setPresence_, que acepta un _status_ y un arreglo _activities_. La primera actividad del arreglo pasa a ser la activa.

```typescript filename="src/listeners/ready.listener.ts"
PresenceManager.setPresence({
  status: 'dnd',
  activities: [{ name: 'maintenance mode', type: 'Playing' }],
});
```

## Cambiar solo el estado

El método _setStatus_ actualiza el indicador de color sin tocar el texto de actividad. Hay cuatro valores disponibles: `'online'` (verde), `'idle'` (amarillo), `'dnd'` (rojo) e `'invisible'` (gris, aparece desconectado). Esto es útil para señalar ventanas de mantenimiento o estados degradados sin cambiar lo que dice la actividad.

```typescript filename="src/services/health.service.ts"
import { PresenceManager } from '@spraxium/core';

PresenceManager.setStatus('idle');
```

## Interpolación de placeholders

Los nombres de actividad admiten placeholders `{{key}}` que se resuelven desde el estado en vivo del cliente cada vez que se actualiza la presencia. Hay cinco variables integradas disponibles sin configuración adicional. Se refrescan automáticamente, así que un contador como `{{totalServers}}` se mantiene correcto cuando se agregan o eliminan guilds.

Los placeholders funcionan en todos los lugares donde se usan actividades: en _setActivity_, _setPresence_, _startRotation_, la configuración de inicio y las sobrescrituras por shard. Si una clave de placeholder no se resuelve, permanece tal cual en la salida (por ejemplo, `{{unknownKey}}`), lo que facilita detectar errores tipográficos.

```typescript filename="src/listeners/ready.listener.ts"
PresenceManager.setActivity({
  name: '{{totalServers}} servers · {{ping}}ms',
  type: 'Watching',
});
```

## Configuración al iniciar

En lugar de llamar a métodos de _PresenceManager_ en un listener, puedes declarar la presencia inicial como una constante tipada en la carpeta `config/` y pasarla a _initPresence_ en el builder de la aplicación en `main.ts`. El framework la aplica automáticamente después de que el cliente se conecta, antes de que se dispare cualquier listener.

<CodeTabs>
  <Tab label="config/presence.config.ts">
```typescript filename="config/presence.config.ts"
import type { PresenceOptions } from '@spraxium/core';

export const presenceConfig: PresenceOptions = {
  status: 'online',
  activities: [{ name: '{{totalServers}} servers', type: 'Watching' }],
};
```
  </Tab>
  <Tab label="src/main.ts">
```typescript filename="src/main.ts"
import { SpraxiumFactory } from '@spraxium/core';
import { presenceConfig } from '../config/presence.config';
import { AppModule } from './app.module';

async function main() {
  const app = await SpraxiumFactory.create({
    token: process.env.DISCORD_TOKEN,
  });
  app.useModule(AppModule);
  app.initPresence(presenceConfig);
  await app.listen();
}

main();

````
  </Tab>
</CodeTabs>

*initPresence* acepta un objeto *PresenceOptions*: un *status*, un arreglo *activities*, un *rotateInterval* para rotación automática y un registro *perShard* para sobrescrituras específicas por shard en el arranque.

## Restablecer al estado de inicio

El método *reset* restaura exactamente la presencia configurada al inicio. Detiene cualquier rotación activa, restablece el estado y la actividad, y vuelve a iniciar la rotación si la configuración inicial especificaba una. Las sobrescrituras por shard en tiempo de ejecución no se limpian con *reset*, así que llama primero a *clearShardPresence* para cada shard si quieres un restablecimiento completo.

```typescript filename="src/commands/reset-presence.command.ts"
PresenceManager.reset();
````
