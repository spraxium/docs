## Qué hace

_spraxium new_ crea un directorio de proyecto nuevo desde cero. Ejecuta un asistente interactivo que recoge nombre de proyecto, plantilla, paquetes extra opcionales y preferencia de Git. Cuando termina el asistente, el CLI hace scaffolding del directorio, instala todas las dependencias y opcionalmente inicializa un repositorio Git. Terminas con un proyecto funcional listo para _spraxium dev_.

Ejecuta el comando desde cualquier directorio fuera de tu proyecto actual. También puedes pasar el nombre del proyecto directamente como argumento para omitir el primer prompt.

```bash filename="terminal"
spraxium new
spraxium new my-bot
# alias:
spraxium n my-bot
```

El principal beneficio de usar el asistente en lugar de crear archivos a mano es la consistencia. Empiezas con la estructura de carpetas, el conjunto de paquetes, la configuración de TypeScript y el wiring del framework que Spraxium espera, lo que reduce limpieza posterior.

## Qué pregunta el asistente

<Steps>
  <Step title="Nombre del proyecto">
    Puedes escribir el nombre del proyecto de forma interactiva o pasarlo por
    línea de comandos. El CLI usa ese nombre para el directorio y los metadatos
    del paquete.
  </Step>
  <Step title="Plantilla">
    Elige el punto de partida que más se parezca al bot que quieres construir.
    Esta elección controla qué archivos y paquetes se precargan.
  </Step>
  <Step title="Paquetes opcionales">
    En la plantilla default, el asistente te permite incluir paquetes
    adicionales del framework para que la instalación inicial encaje con tu caso
    de uso.
  </Step>
  <Step title="Inicialización de Git">
    Decide si el CLI debe inicializar un repositorio Git inmediatamente. Es
    conveniente para proyectos nuevos, pero opcional.
  </Step>
</Steps>

## Plantillas disponibles

Hay tres plantillas disponibles. Cada una representa una configuración inicial distinta, y el asistente te deja elegir entre ellas antes del scaffolding.

<DropdownGroup>
<Dropdown title="default">
  Un bot de Discord mínimo que solo incluye los paquetes core. Después de elegir esta plantilla, el asistente muestra una lista de módulos opcionales para que actives exactamente lo que necesitas. Úsala cuando quieras control total sobre lo que entra en tu proyecto desde el principio.
</Dropdown>

<Dropdown title="slash-bot">
  Un bot de Discord con un slash command `/ping` listo para usar y ya cableado.
  El comando, su handler y el registro del módulo se generan previamente para
  que puedas ejecutar *spraxium dev* de inmediato y ver la respuesta. Úsala como
  punto de partida cuando los slash commands sean tu modelo principal de
  interacción.
</Dropdown>

<Dropdown title="http-bot">
  Un bot de Discord con una API REST ligera integrada mediante *@spraxium/http*. El módulo HTTP ya viene registrado junto al bot. Úsala cuando tu bot necesite exponer endpoints además de las interacciones de Discord.
</Dropdown>
</DropdownGroup>

Elige la plantilla más pequeña que aun así encaje con la forma del proyecto que sabes que necesitas. Es más fácil añadir un paquete después que cargar piezas sin uso desde el día uno.

## Paquetes opcionales

Cuando eliges la plantilla _default_, el asistente muestra un prompt de casillas donde puedes seleccionar cualquier combinación de los siguientes paquetes extra. Las plantillas no default usan un conjunto fijo.

<DropdownGroup>
<Dropdown title="@spraxium/components">
  Agrega el *ComponentsModule* para construir componentes interactivos de UI en Discord, como botones, menús de selección y modales con decorators.
</Dropdown>

<Dropdown title="@spraxium/http">
  Agrega el *HttpModule* para crear endpoints REST junto a tu bot de Discord en
  el mismo proceso.
</Dropdown>

<Dropdown title="@spraxium/schedule">
  Agrega el *ScheduleModule* para tareas cron, timeouts de una sola ejecución e
  intervalos usando scheduling basado en decorators.
</Dropdown>

<Dropdown title="@spraxium/i18n">
  Agrega el *I18nModule* para soporte multilenguaje con archivos de locale y
  servicios de traducción inyectables.
</Dropdown>

<Dropdown title="@spraxium/signal">
  Agrega el bus de eventos server-side *@spraxium/signal*. Úsalo cuando el bot
  necesite publicar eventos tipados a clientes conectados.
</Dropdown>

<Dropdown title="@spraxium/signal-client">
  Agrega *@spraxium/signal-client* para suscribirte a eventos desde un servidor Signal. Úsalo junto con *@spraxium/signal* o en microservicios independientes.
</Dropdown>
</DropdownGroup>

Si estás empezando, la opción más segura suele ser comenzar con lo mínimo y añadir paquetes cuando aparezca el primer caso de uso real. Para equipos con experiencia y arquitectura definida, preseleccionar los paquetes correctos desde el inicio reduce la primera ronda de ajustes.

## Qué instala el asistente

El CLI siempre instala un conjunto fijo de paquetes core, sin importar la plantilla: _@spraxium/common_, _@spraxium/core_, _@spraxium/env_ y _discord.js_. Las dependencias de desarrollo incluyen _@spraxium/cli_, _typescript_, _@types/node_ y _tsdown_.

Cualquier paquete extra que selecciones se añade en la misma pasada de instalación. El instalador detecta si estás dentro de un monorepo y resuelve referencias locales de workspace cuando corresponde. Si no detecta un package manager, el CLI usa pnpm por defecto.

## Qué obtienes inmediatamente después de la generación

Cuando el comando termina, ya tienes lo esencial:

1. Un directorio de proyecto funcional.
2. Una carpeta _src_ lista para editar con los archivos iniciales de la plantilla.
3. Un archivo _spraxium.config.ts_ alineado con la configuración elegida.
4. Dependencias instaladas.
5. Un repositorio Git opcional si lo activaste.

Eso es suficiente para pasar directo a la configuración de entorno y a _spraxium dev_ sin una fase de bootstrap manual separada.

<Callout tone="warning" title="El directorio no debe existir">
  Si ya existe un directorio con ese nombre de proyecto en la ruta actual, el
  comando se detiene inmediatamente sin escribir archivos. Renombra o elimina el
  directorio en conflicto antes de ejecutar el asistente otra vez.
</Callout>

## Siguientes pasos recomendados

Después del scaffolding, la secuencia habitual es:

1. Completar las variables de entorno.
2. Ejecutar _spraxium dev_ una vez para confirmar que la app arranca.
3. Usar _spraxium generate_ para agregar el primer módulo, servicio o comando real.

Así mantienes el proyecto avanzando en pasos pequeños y verificables, en lugar de añadir mucho código antes del primer arranque exitoso.
