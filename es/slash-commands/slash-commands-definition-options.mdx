## La clase de definición del comando

Una definición de slash command es una clase decorada con _@SlashCommand_ que declara qué debe mostrar Discord en el selector de comandos. La clase en sí no contiene lógica de ejecución. Su propósito es almacenar metadatos que el _SlashRegistrar_ lee al iniciar para construir el payload JSON que se envía a la API REST de Discord. Las opciones se declaran como decoradores de método sobre un método _build()_, y los subcomandos se declaran sobre métodos con nombre. La clase puede importarse por handlers, handlers de autocomplete y fixtures de prueba sin arrastrar dependencias de servicios.

El decorador _@SlashCommand_ acepta un objeto _SlashCommandConfig_ con las siguientes propiedades. Todo comando debe proporcionar al menos _name_ y _description_. Las propiedades restantes controlan permisos por defecto, disponibilidad en DM, flag NSFW, registro específico por guild y localización.

<DropdownGroup>
  <Dropdown title="name, string (required)">
    El nombre del comando mostrado en el selector de Discord. Debe estar en
    minúsculas, entre 1 y 32 caracteres, sin espacios. Este es el identificador
    que Discord usa para enrutar la interacción hacia tu bot. Cambiar el nombre
    de un comando después del registro crea una nueva entrada en el registro de
    Discord; el nombre anterior no se elimina automáticamente hasta que fuerces
    un nuevo registro.
  </Dropdown>
  <Dropdown title="description, string (required)">
    La descripción mostrada debajo del nombre del comando en el selector de
    Discord. Acepta -00 caracteres. Escribe una descripción breve y orientada a
    la acción para que los usuarios entiendan el propósito del comando antes de
    invocarlo. Las descripciones son indexadas por Discord para búsqueda, por lo
    que una redacción clara mejora la descubribilidad del comando.
  </Dropdown>
  <Dropdown title="defaultMemberPermissions, bigint | number | null">
    Bitfield de permisos requerido para ver y usar el comando. Usa
    `PermissionFlagsBits` de discord.js para componer el valor. Cuando se
    establece, Discord oculta el comando para miembros que no tengan los
    permisos especificados. Establécelo en `null` para que el comando sea
    visible para todos por defecto. Los administradores del guild pueden
    sobrescribir esto por guild en la configuración del servidor.
  </Dropdown>
  <Dropdown title="dmPermission, boolean">
    Controla si el comando está disponible en mensajes directos. Por defecto es
    `true` cuando se omite. Establécelo en `false` para comandos que requieren
    contexto de guild, como aquellos que leen miembros o canales del guild. Este
    flag no tiene efecto en comandos solo de guild registrados mediante la
    propiedad *guild*.
  </Dropdown>
  <Dropdown title="nsfw, boolean">
    Marca el comando como restringido por edad. Cuando es `true`, el comando
    solo aparece en canales marcados como NSFW y en DMs para usuarios que ya
    aceptaron restricciones de edad. Usa este flag para comandos que presenten
    contenido solo para adultos y cumplir con las políticas de Discord.
  </Dropdown>
  <Dropdown title="guild, string">
    ID del guild para registro específico por guild. Cuando se proporciona, el
    comando se registra solo en ese guild y omite el registro global. Los
    comandos de guild se propagan en segundos en lugar del retraso de hasta una
    hora de los comandos globales. Elimina la propiedad *guild* antes de
    desplegar en producción para registrar el comando globalmente.
  </Dropdown>
  <Dropdown title="i18n, SlashI18nKeys">
    Claves de localización para el nombre y la descripción del comando,
    resueltas mediante el módulo i18n. Proporciona un objeto *SlashI18nKeys* con
    claves string *name* y *description* que mapeen a entradas en tus archivos
    de locale. Los campos base *name* y *description* se usan como fallback
    cuando no se encuentra un locale compatible para el idioma del cliente de
    Discord del usuario.
  </Dropdown>
</DropdownGroup>

```typescript filename="commands/ban.command.ts"
import { SlashCommand, SlashOption } from '@spraxium/common';
import { PermissionFlagsBits } from 'discord.js';

@SlashCommand({
  name: 'ban',
  description: 'Ban a member from the server.',
  defaultMemberPermissions: PermissionFlagsBits.BanMembers,
})
export class BanCommand {
  @SlashOption.User('target', {
    description: 'The member to ban',
    required: true,
  })
  @SlashOption.String('reason', {
    description: 'Reason for the ban',
    required: false,
    maxLength: 512,
  })
  @SlashOption.Integer('days', {
    description: 'Number of days of messages to delete',
    required: false,
    min: 0,
    max: 7,
  })
  build() {}
}
```

## Tipos de opción

Spraxium proporciona nueve decoradores de tipos de opción a través del namespace _SlashOption_, uno por cada tipo de opción de application command de Discord. Cada decorador es un decorador de método aplicado al método _build()_ de la clase de comando (o a un método _@SlashSubcommand_ cuando la opción pertenece a un subcomando). Las opciones se apilan en el mismo método, y el orden de los decoradores determina el orden de visualización en el cliente de Discord (el decorador superior aparece al final en el selector).

<DropdownGroup>
  <Dropdown title="@SlashOption.String, string | null">
    Mapea al tipo de opción STRING de Discord. El handler recibe un `string`
    cuando el usuario proporciona un valor, o `null` cuando la opción no es
    requerida y se omitió. Soporta *minLength*, *maxLength*, *choices* (lista
    estática desplegable) y *autocomplete* (sugerencias dinámicas). Ten en
    cuenta que *choices* y *autocomplete* no se pueden combinar en la misma
    opción.
  </Dropdown>
  <Dropdown title="@SlashOption.Integer, number | null">
    Mapea al tipo de opción INTEGER de Discord. Acepta solo números enteros. El
    handler recibe un `number` o `null`. Soporta *min* y *max* para validación
    de rango, *choices* para un conjunto fijo de enteros y *autocomplete* para
    sugerencias dinámicas.
  </Dropdown>
  <Dropdown title="@SlashOption.Number, number | null">
    Mapea al tipo de opción NUMBER de Discord. Acepta números de punto
    flotante. El handler recibe un `number` o `null`. Soporta *min* y *max* para
    validación de rango y *autocomplete* para sugerencias dinámicas. *choices*
    estáticos no está disponible para el tipo Number.
  </Dropdown>
  <Dropdown title="@SlashOption.Boolean, boolean | null">
    Mapea al tipo de opción BOOLEAN de Discord. Discord lo renderiza como un
    interruptor true/false en el selector de comandos. El handler recibe `true`,
    `false` o `null` cuando la opción es opcional y no fue proporcionada. No hay
    restricciones adicionales para este tipo.
  </Dropdown>
  <Dropdown title="@SlashOption.User, User | null">
    Mapea al tipo de opción USER de Discord. Discord renderiza un selector de
    usuario. El handler recibe un objeto *User* de discord.js completamente
    resuelto, o `null` si la opción es opcional y no fue completada. No hay
    restricciones adicionales para este tipo.
  </Dropdown>
  <Dropdown title="@SlashOption.Channel, Channel | null">
    Mapea al tipo de opción CHANNEL de Discord. Discord renderiza un selector de
    canal. El handler recibe un objeto *Channel* o `null`. Soporta el arreglo
    *channelTypes* para restringir qué tipos de canal puede seleccionar el
    usuario. Consulta la sección de filtrado por tipo de canal más abajo para la
    lista completa de valores aceptados.
  </Dropdown>
  <Dropdown title="@SlashOption.Role, Role | null">
    Mapea al tipo de opción ROLE de Discord. Discord renderiza un selector de
    rol. El handler recibe un objeto *Role* de discord.js completamente
    resuelto, o `null` si la opción es opcional y no fue completada. No hay
    restricciones adicionales para este tipo.
  </Dropdown>
  <Dropdown title="@SlashOption.Mentionable, User | Role | null">
    Mapea al tipo de opción MENTIONABLE de Discord. Acepta tanto usuarios como
    roles. El handler recibe un objeto *User* o *Role* según lo seleccionado, o
    `null` si es opcional y se omitió. No hay restricciones adicionales para
    este tipo.
  </Dropdown>
  <Dropdown title="@SlashOption.Attachment, Attachment | null">
    Mapea al tipo de opción ATTACHMENT de Discord. Discord renderiza un campo de
    carga de archivo. El handler recibe un objeto *Attachment* de discord.js con
    metadatos y una URL CDN, o `null` si la opción es opcional y no fue
    completada. No hay restricciones adicionales para este tipo.
  </Dropdown>
</DropdownGroup>

Cada decorador de opción acepta dos argumentos posicionales: el _name_ de la opción (string, usado para registro en Discord y para coincidencia con _@SlashOpt_) y un objeto _config_. El objeto config extiende _SlashBaseOptionConfig_ con campos específicos del tipo.

## Restricciones de opciones String

El decorador _@SlashOption.String_ soporta cuatro propiedades de configuración adicionales además de la configuración base. Estas propiedades mapean directamente a las restricciones de la API de Discord para opciones string y te permiten controlar longitud de entrada, proveer choices fijos o habilitar sugerencias de autocomplete.

```typescript filename="commands/echo.command.ts"
import { SlashCommand, SlashOption } from '@spraxium/common';

@SlashCommand({
  name: 'echo',
  description: 'Repeat a message back to the channel.',
})
export class EchoCommand {
  @SlashOption.String('message', {
    description: 'Text to echo',
    required: true,
    minLength: 1,
    maxLength: 2000,
      <TableCell>0</TableCell>
  build() {}
}
```

Cuando se establece _minLength_ o _maxLength_, Discord valida la longitud de entrada del lado del cliente antes de enviar la interacción. Cuando se proporciona _choices_, el usuario selecciona desde un desplegable en lugar de escribir libremente. Cuando _autocomplete_ se establece en `true`, Discord llama a tu handler de autocomplete mientras el usuario escribe, proporcionando sugerencias dinámicas en tiempo real desde tu código.

## Restricciones de opciones numéricas

## Filtrado por tipo de canal

El decorador _@SlashOption.Channel_ acepta un arreglo _channelTypes_ que restringe qué tipos de canal puede seleccionar el usuario. Los valores corresponden a miembros del enum _ChannelType_ de Discord. Cuando se proporciona el arreglo, el cliente de Discord solo muestra canales que coinciden con los tipos especificados en el selector de opción.

```typescript filename="commands/setup.command.ts"
import { SlashCommand, SlashOption } from '@spraxium/common';
import { ChannelType } from 'discord.js';

@SlashCommand({
  name: 'setup',
  description: 'Configure the bot for this server.',
})
export class SetupCommand {
  @SlashOption.Channel('log-channel', {
    description: 'Channel for bot logs',
    required: true,
    channelTypes: [ChannelType.GuildText, ChannelType.GuildAnnouncement],
  })
  @SlashOption.Channel('voice-channel', {
    description: 'Default voice channel',
    required: false,
    channelTypes: [ChannelType.GuildVoice, ChannelType.GuildStageVoice],
  })
  build() {}
}
```

## Localización con claves i18n

Tanto el decorador _@SlashCommand_ como cada decorador _@SlashOption_ aceptan una propiedad opcional _i18n_ de tipo _SlashI18nKeys_. Este objeto contiene dos claves string, _name_ y _description_, que el módulo i18n resuelve a strings específicos por locale durante el registro del comando. Las localizaciones resueltas se envían a Discord como parte del payload del comando, de modo que los usuarios ven nombres de comandos y opciones en el idioma de su cliente de Discord.

```typescript filename="commands/locale.command.ts"
import { SlashCommand, SlashOption } from '@spraxium/common';

@SlashCommand({
  name: 'locale',
  description: 'Change your preferred language.',
  i18n: {
    name: 'commands.locale.name',
    description: 'commands.locale.description',
  },
})
export class LocaleCommand {
  @SlashOption.String('language', {
    description: 'The language to use.',
    required: true,
    i18n: {
      name: 'commands.locale.options.language.name',
      description: 'commands.locale.options.language.description',
    },
    choices: [
      { name: 'English (US)', value: 'en-US' },
      { name: 'Português (Brasil)', value: 'pt-BR' },
    ],
  })
  build() {}
}
```

Las claves _i18n_ siguen el mismo patrón de resolución que el resto del sistema i18n del framework. Mapean a claves en tus archivos JSON de locale y soportan todos los locales admitidos por Discord. Cuando un usuario con cliente de Discord en portugués brasileño abre el selector de comandos, ve automáticamente los nombres traducidos de comandos y opciones.

## Checklist de diseño para definiciones de comandos

<Steps>
  <Step title="Mantén las definiciones libres de lógica de negocio">
    La clase del comando debe contener solo decoradores de metadatos y un método
    *build()* vacío (o métodos con nombre para subcomandos). Nunca importes
    servicios, repositorios o dependencias de runtime en un archivo de
    definición de comando. Esto asegura que la clase pueda ser importada por
    handlers, handlers de autocomplete y pruebas sin crear cadenas de
    dependencia.
  </Step>
  <Step title="Usa el tipo de opción más específico disponible">
    Prefiere *@SlashOption.User* sobre *@SlashOption.String* para IDs de
    usuario, *@SlashOption.Channel* sobre *@SlashOption.String* para
    referencias de canal y *@SlashOption.Integer* sobre *@SlashOption.Number*
    para números enteros. Los tipos específicos dan a Discord mejores affordances
    de UI como selectores de usuario y dropdowns de canales, y el handler recibe
    objetos de discord.js completamente resueltos en lugar de strings en bruto.
  </Step>
  <Step title="Restringe canales con channelTypes">
    Cuando un comando espera un tipo específico de canal, siempre proporciona el
    arreglo *channelTypes*. Esto evita que los usuarios seleccionen canales de
    voz cuando esperas canales de texto, y el cliente de Discord aplica la
    restricción antes de que la interacción llegue al bot.
  </Step>
  <Step title="Prefiere choices sobre autocomplete para conjuntos pequeños">
    Los arreglos estáticos de *choices* se muestran como un dropdown y no
    requieren código de handler. Úsalos cuando el conjunto de valores válidos es
    pequeño y fijo (menos de 25 entradas). Usa *autocomplete* cuando los valores
    son dinámicos, vienen de una base de datos o superan el límite de 25 choices.
  </Step>
  <Step title="Define permisos en la capa de definición">
    Usa *defaultMemberPermissions* para establecer los permisos mínimos
    necesarios para ver el comando en el selector. Esta es una pista de UI que
    Discord aplica del lado del cliente. Combínalo con *@UseGuards* en el handler
    para una aplicación del lado del servidor que no pueda eludirse.
  </Step>
</Steps>
