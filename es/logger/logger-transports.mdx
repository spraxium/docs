## Configurar el logger

Mantén la configuración del logger en un archivo dedicado _config/logger.config.ts_ y referencia ese archivo desde _spraxium.config.ts_. Así mantienes legible la configuración raíz y dejas claro dónde se definen los niveles de log, el masking, los timestamps y el envío a Discord.

El framework aplica esta configuración durante el bootstrap, antes de que tus providers empiecen a emitir logs. En la práctica, esto significa que la primera línea que escribe tu bot ya usa el formato de timestamp, los niveles personalizados y los transports configurados.

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  levels: [
    { name: 'audit', color: 'blueBright' },
    { name: 'payment', color: 'greenBright' },
  ],
  maskTokens: true,
  discord: {
    type: 'channel',
    channelId: '1234567890',
    levels: ['error', 'warn', 'command'],
  },
};
```

```typescript filename="spraxium.config.ts"
import { defineConfig } from '@spraxium/core';
import { loggerConfig } from './config/logger.config';

export default defineConfig((_env) => ({
  logger: loggerConfig,
}));
```

El arreglo _levels_ registra niveles de log personalizados junto con sus colores de consola. Esos niveles quedan disponibles mediante _Logger.extend_ y son entendidos por ambos transports integrados. La bandera _maskTokens_ controla _TokenMasker_, que está habilitado por defecto. Desactívala solo en sesiones de depuración local muy controladas.

## Formato de timestamp

La opción _timestampFormat_ controla el prefijo que se muestra antes de cada línea de log en consola. Elige uno de los presets integrados si quieres consistencia con el resto del framework, o proporciona un formatter personalizado cuando tu bot integra logs en un estándar local ya existente.

## El transport de Discord

El transport de Discord reenvía entradas de log seleccionadas como embeds a Discord. Solo envía los niveles listados en su propio arreglo _levels_, así que puedes mantener en terminal los logs operativos de alto volumen y reenviar advertencias, errores o auditorías de comandos a un canal compartido.

Hay dos modos de entrega disponibles. En modo _channel_, el transport usa el propio cliente del bot para buscar el canal y enviar embeds. En modo _webhook_, envía solicitudes HTTP a una URL de webhook, lo cual resulta útil cuando el destino está operativamente separado del runtime del bot.

En modo channel, el transport encola mensajes que llegan antes de que el cliente esté listo. Una vez que el cliente emite _ready_, la cola se vacía automáticamente. La cola tiene un tamaño máximo de 100 entradas para evitar crecimiento de memoria durante secuencias largas de arranque.

El transport también deduplica entradas. Si se envían el mismo nivel, contexto y mensaje dentro de un segundo, el segundo envío se suprime. Esto protege los canales operativos frente a ráfagas duplicadas accidentales causadas por rutas de reintento o handlers de eventos superpuestos.

## Plantillas de embed personalizadas

De forma predeterminada, los embeds de Discord usan el nivel como título, el mensaje como descripción, un color correspondiente y un timestamp ISO. Sobrescribe esto con una plantilla _embed_ personalizada cuando quieras un layout más operativo, por ejemplo incluyendo shard, guild o fields de metadata en posiciones predecibles.

````typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  discord: {
    type: 'channel',
    channelId: '1234567890123456789',
    levels: ['error', 'warn', 'command'],
    embed: {
      title: '{{level}} Log',
      description: "```\n{{message}}\n```",
      color: 0xff6b6b,
      timestamp: true,
      footer: { text: "Shard {{shard}} \u00b7 {{date}} {{time}}" },
      fields: [
        { name: 'Context', value: '{{context}}', inline: true },
        { name: 'Level', value: '{{level}}', inline: true },
      ],
    },
  },
};
````

Las variables placeholder disponibles se resuelven desde la entrada de log en el momento del envío. La variable _shard_ muestra el ID de shard cuando el bot usa sharding, o "N/A" en un solo proceso. La metadata pasada mediante _log_ también se expone como placeholders, y eso es lo que hace especialmente útiles los logs de comando y auditoría en Discord.

## Registro de comandos

El servicio _CommandLogger_ registra automáticamente cada ejecución de slash command. Se enlaza al evento _interactionCreate_ del cliente y captura nombre del comando, tag del usuario, ID de usuario, nombre del guild, ID del guild e ID del canal. Cada ejecución emite una entrada de log en el nivel _command_ con metadata estructurada que puedes reutilizar en plantillas de embed.

La forma estándar de habilitar el registro de comandos es mediante _spraxium.config.ts_. Establece _commandLogging_ en _true_ dentro del bloque logger y el framework llama a _CommandLogger.bind_ automáticamente durante el cableado del cliente. Esta es la configuración recomendada para la mayoría de bots porque se mantiene dentro del ciclo de vida normal del framework.

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  maskTokens: true,
  commandLogging: true,
  discord: {
    type: 'channel',
    channelId: '1234567890123456789',
    levels: ['command'],
    embed: {
      title: 'Command Executed',
      description: '`/{{command}}` by **{{user}}**',
      timestamp: true,
      footer: { text: '{{guild}} ({{guildId}})' },
    },
  },
};
```

Si usas el logger fuera del framework o necesitas enlazar el registro de comandos manualmente, llama a _CommandLogger.bind_ directamente con el cliente de Discord después de que esté listo. La metadata de comando, usuario, guild y canal queda entonces disponible para tu plantilla de embed.

```typescript filename="src/main.ts"
import { CommandLogger } from '@spraxium/logger';

// Call after the client is ready
CommandLogger.bind(client);
```

## Transports personalizados

Crea un transport personalizado cuando la salida en consola y el envío a Discord no sean suficientes, por ejemplo al escribir en archivos, stacks externos de observabilidad o buses de eventos internos. Un transport implementa _LogTransport_, expone un _name_ y proporciona un método _log_ que recibe un _LogEntry_.

Los fallos de transport están aislados del resto de la app. Si un transport lanza una excepción o rechaza, el logger absorbe ese fallo para que el logging nunca se convierta en un punto único de falla para el runtime de tu bot.

```typescript filename="src/transports/file.transport.ts"
import { appendFileSync } from 'node:fs';
import type { LogEntry, LogTransport } from '@spraxium/logger';

export class FileTransport implements LogTransport {
  readonly name = 'file';

  constructor(private readonly path: string) {}

  log(entry: LogEntry): void {
    const line = `[${entry.timestamp.toISOString()}] ${entry.level.toUpperCase()} ${entry.context ?? ''} ${entry.message}\n`;
    appendFileSync(this.path, line);
  }
}
```

Registra el transport con _Logger.addTransport_. Si ya existe un transport con el mismo nombre, se reemplaza. Puedes eliminar un transport por nombre con _Logger.removeTransport_. _ConsoleTransport_ siempre se registra por defecto y usa el nombre `"console"`.

```typescript filename="src/main.ts"
import { Logger } from '@spraxium/logger';
import { FileTransport } from './transports/file.transport';

Logger.addTransport(new FileTransport('./logs/bot.log'));
```

Si tu transport necesita el cliente de Discord (por ejemplo, para resolver nombres de canal o datos de guild), implementa la interfaz _ClientAwareTransport_ en su lugar. Agrega un método _setClient_ que el framework llama automáticamente cuando el cliente está listo. El _DiscordTransport_ integrado usa esta interfaz internamente.
