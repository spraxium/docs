## debug

El flag _debug_ habilita salida diagnóstica adicional en todos los subsistemas. Cuando está activo, el framework emite líneas de traza extra durante la carga de módulos, la resolución de providers, el registro de comandos y el dispatch de interacciones. Esta salida está pensada para troubleshooting y no debería mantenerse activa en despliegues de producción de alto throughput.

El flag acepta un booleano simple o cualquier expresión _ConfigEnv_, para que puedas limitar la verbosidad a un entorno específico.

## logger

El bloque _logger_ controla la política de salida del logger integrado. No afecta la lógica de negocio. Las opciones más configuradas son _maskTokens_ (reemplaza strings con apariencia de token por un placeholder seguro), _commandLogging_ (emite una línea de traza en cada dispatch de comando) y _discord_ (envía niveles de log seleccionados a un canal webhook).

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/core';

export const loggerConfig: SpraxiumLoggerConfig = {
  maskTokens: true,
  commandLogging: true,
  discord: {
    type: 'channel',
    webhookUrl: process.env.LOGGER_WEBHOOK!,
    levels: ['error', 'warn'],
    channelId: '1462519588775395429',
  },
};
```

## plugins

El array _plugins_ reúne entradas devueltas por factories de plugins. Cada entrada contiene un string _namespace_ y una carga de configuración tipada; el framework usa ese namespace para enrutar la configuración al plugin correcto en runtime. Las factories de plugins y las opciones oficiales se cubren en la página de Registro de plugins.

## dev

El bloque _dev_ tiene una página de referencia dedicada más adelante en esta categoría, donde se cubren todos los campos del watcher, los nombres de archivo de configuración admitidos y cómo se resuelven los entornos al iniciar.

El bloque _prefix_ está completamente documentado en la categoría de Comandos de prefijo. El bloque _exceptions_ está completamente documentado en la categoría de Excepciones.
