## Rutas de fallo

Cuando un comando con prefijo falla en cualquier etapa, el framework produce una excepción específica que puedes interceptar y formatear. Entender la taxonomía de fallos te ayuda a diseñar respuestas de error amigables para usuarios en lugar de dejar que errores crudos se filtren al chat. Cada tipo de fallo corresponde a una clase de excepción distinta con su propio hook de layout.

<DropdownGroup>
  <Dropdown title="CommandNotFoundException (unknown command)">
    Se lanza cuando se reconoce el prefijo pero el nombre del comando no
    coincide con ninguna entrada en el registro. La excepción expone como
    propiedades el nombre de *command* intentado y el *prefix* coincidente.
    Puedes interceptarla con un layout de excepciones para enviar una respuesta
    útil, o habilitar *replyOnNotFound* en *PrefixConfig* para feedback
    automático sin layout personalizado.
  </Dropdown>
  <Dropdown title="ArgumentException (missing or invalid argument)">
    Se lanza cuando falta un argumento requerido o cuando la coerción de tipo o
    la validación falla para un valor proporcionado. La excepción expone el
    *name* del argumento, la restricción *expected*, la entrada cruda
    *received* y el string *usage* de la definición del comando. Registra un
    layout para *ArgumentException* para mostrar mensajes de error consistentes
    en todos los comandos.
  </Dropdown>
  <Dropdown title="ForbiddenException or custom (guard denial)">
    Se lanza cuando el método *canActivate* de un guard devuelve `false` o
    lanza una excepción. Si el guard devuelve `false`, el framework lanza una
    *ForbiddenException* automáticamente. Si el guard lanza su propia excepción,
    esa excepción se propaga sin cambios y puede capturarse con un layout
    compatible.
  </Dropdown>
  <Dropdown title="Cooldown active (silently blocked)">
    Cuando un usuario activa un comando antes de que expire el cooldown, el
    framework bloquea la ejecución silenciosamente sin lanzar excepción. Puedes
    leer los segundos restantes desde *PrefixCooldownManager.check* y enviar una
    respuesta personalizada desde un cooldown guard si quieres feedback visible
    para el usuario.
  </Dropdown>
</DropdownGroup>

## Layouts de excepciones

Los layouts de excepciones te permiten definir respuestas personalizadas para tipos de excepción concretos. En lugar de escribir bloques try-catch en cada handler, registras un layout una sola vez y el framework lo aplica automáticamente siempre que ese tipo de excepción se lance durante la ejecución de comandos con prefijo. Esto mantiene limpios tus handlers y hace consistente el formato de errores en todo el bot.

Un layout recibe el _Message_ original y la excepción lanzada, para que puedas construir embeds de error ricos con contexto sobre qué salió mal. El helper _defineExceptionLayout_ crea una fábrica de layouts que el framework descubre mediante el registro de tu módulo.

<CodeTabs>
  <Tab label="Argument layout" language="typescript">
```typescript filename="src/modules/prefix/layouts/argument-exception.layout.ts"
import { defineExceptionLayout } from '@spraxium/core';
import { ArgumentException } from '@spraxium/common';

export const ArgumentExceptionLayout = defineExceptionLayout(
  ArgumentException,
  async (message, exception) => {
    await message.reply({
      content: `Invalid argument: **${exception.argName}** - ${exception.message}`,
    });
  },
);
```
  </Tab>
  <Tab label="Not found layout" language="typescript">
```typescript filename="src/modules/prefix/layouts/not-found.layout.ts"
import { defineExceptionLayout } from '@spraxium/core';
import { CommandNotFoundException } from '@spraxium/common';

export const CommandNotFoundLayout = defineExceptionLayout(
  CommandNotFoundException,
  async (message, exception) => {
    await message.reply({
      content: `Command \`${exception.commandName}\` not found. Use \`!help\` to see available commands.`,
    });
  },
);
```
  </Tab>
</CodeTabs>

Registra layouts en tu módulo junto a comandos y handlers. El framework los detecta durante la inicialización del módulo y los aplica automáticamente a los tipos de excepción correctos.

```typescript filename="src/modules/prefix/prefix.module.ts"
import { Module } from '@spraxium/common';
import { RollCommand } from './commands/roll.command';
import { RollHandler } from './handlers/roll.handler';
import { ArgumentExceptionLayout } from './layouts/argument-exception.layout';
import { CommandNotFoundLayout } from './layouts/not-found.layout';

@Module({
  commands: [RollCommand],
  handlers: [RollHandler],
  layouts: [ArgumentExceptionLayout, CommandNotFoundLayout],
})
export class PrefixModule {}
```

## Introspección del dispatcher

El _PrefixDispatcher_ expone métodos para inspeccionar en runtime el árbol de comandos registrados. El método _getCommandInfo_ devuelve un arreglo de objetos _PrefixCommandInfo_ con nombres de comandos, descripciones, listas de subcomandos y esquemas de argumentos. Esta es la base para construir comandos de ayuda dinámicos.

El dispatcher también expone _getResolved_ para los bindings comando-handler completamente resueltos, _size_ para el número total de entradas registradas, _commandCount_ para comandos de nivel superior distintos y _guildPrefixes_ para el manager de prefijos por guild. Estos métodos de introspección son útiles para paneles administrativos, health checks y herramientas de depuración.

```typescript filename="src/modules/prefix/handlers/help-command.handler.ts"
import { Ctx, PrefixCommandHandler } from '@spraxium/common';
import { PrefixDispatcher } from '@spraxium/core';
import type { Message } from 'discord.js';
import { HelpCommand } from '../commands/help.command';

@PrefixCommandHandler(HelpCommand)
export class HelpHandler {
  constructor(private readonly dispatcher: PrefixDispatcher) {}

  async handle(@Ctx() message: Message): Promise<void> {
    const commands = this.dispatcher.getCommandInfo();
    const lines = commands.map((cmd) => {
      const subs = cmd.subcommands?.map((s) => s.name).join(', ');
      return subs
        ? `**${cmd.name}** - subcommands: ${subs}`
        : `**${cmd.name}**`;
    });
    await message.reply(lines.join('\n') || 'No commands registered.');
  }
}
```

## Guards con comandos con prefijo

Los comandos con prefijo soportan el mismo sistema de guards usado por slash commands y listeners. Decora una clase handler con _@UseGuards_ para adjuntar uno o más guards que se ejecutan antes de que el handler se ejecute. Si cualquier guard devuelve `false` o lanza una excepción, el handler se omite. Los guards son útiles para comprobaciones de permisos, restricciones por rol y filtrado por tipo de canal.

Los guards reciben el contexto de ejecución, que para comandos con prefijo incluye el objeto _Message_ original. Puedes usar las mismas clases guard en comandos con prefijo, slash commands y listeners sin modificaciones. Este es uno de los beneficios de la arquitectura unificada de guards.

<CodeTabs>
  <Tab label="Guard" language="typescript">
```typescript filename="src/modules/moderation/guards/moderator.guard.ts"
import { CanActivate, ExecutionContext } from '@spraxium/common';

export class ModeratorGuard implements CanActivate {
  async canActivate(context: ExecutionContext): Promise<boolean> {
    const message = context.getMessage();
    const member = message.member;
    if (!member) return false;
    return member.permissions.has('ModerateMembers');
  }
}
```
  </Tab>
  <Tab label="Handler with guard" language="typescript">
```typescript filename="src/modules/moderation/handlers/ban-command.handler.ts"
import { Ctx, PrefixArg, PrefixCommandHandler, UseGuards } from '@spraxium/common';
import type { Message } from 'discord.js';
import { ModeratorGuard } from '../guards/moderator.guard';
import { ModCommand } from '../commands/mod.command';

@UseGuards(ModeratorGuard)
@PrefixCommandHandler(ModCommand, { subcommand: 'ban' })
export class BanHandler {
  async handle(
    @Ctx() message: Message,
    @PrefixArg('target') targetId: string,
    @PrefixArg('reason') reason: string | undefined,
  ): Promise<void> {
    await message.guild?.members.ban(targetId, { reason: reason ?? 'No reason provided' });
    await message.reply(`Banned <@${targetId}>.`);
  }
}

```
  </Tab>
</CodeTabs>
