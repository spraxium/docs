## debug

A flag _debug_ habilita saída extra de diagnóstico em todos os subsistemas. Quando está ativa, o framework emite linhas adicionais de rastreamento durante o carregamento de módulos, a resolução de providers, o registro de commands e o despacho de interações. Essa saída é voltada para troubleshooting e não deve permanecer ativa em implantações de produção com alto volume.

A flag aceita um boolean simples ou qualquer expressão _ConfigEnv_, então você pode limitar a verbosidade a um ambiente específico.

## logger

O bloco _logger_ controla a política de saída do logger embutido. Ele não afeta a lógica de negócio. As opções configuradas com mais frequência são _maskTokens_ , que substitui strings parecidas com token por um placeholder seguro, _commandLogging_, que emite uma linha de rastreamento a cada despacho de command, e _discord_, que envia níveis selecionados de log para um canal de webhook.

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/core';

export const loggerConfig: SpraxiumLoggerConfig = {
  maskTokens: true,
  commandLogging: true,
  discord: {
    type: 'channel',
    webhookUrl: process.env.LOGGER_WEBHOOK!,
    levels: ['error', 'warn'],
    channelId: '1462519588775395429',
  },
};
```

## plugins

O array _plugins_ reúne as entradas retornadas pelas factories de plugin. Cada entrada carrega uma string _namespace_ e uma carga de configuração tipada; o framework usa o namespace para encaminhar a config ao plugin correto em runtime. As factories de plugin e as opções de primeira parte são abordadas na página de Registro de plugins.

## dev

O bloco _dev_ tem uma página de referência dedicada mais adiante nesta categoria, cobrindo todos os campos do watcher, os nomes de arquivo de configuração aceitos e como os ambientes são resolvidos na inicialização.

O bloco _prefix_ está totalmente documentado na categoria Prefix Commands. O bloco _exceptions_ está totalmente documentado na categoria Exceptions.
