## Tipos de menu de seleção

O Discord oferece cinco variantes de select menu, e o Spraxium dá suporte a todas elas com decorators dedicados. String selects permitem definir opções personalizadas com rótulo e valor. Já os selects de user, role, mentionable e channel usam os seletores nativos do Discord, que se preenchem automaticamente com dados do servidor. Os cinco tipos compartilham o mesmo padrão de handler e o mesmo sistema de injeção de parâmetros.

Cada tipo é definido como uma classe decorada, vinculado a um handler por meio de um decorator específico e renderizado via _SelectService_. A principal diferença entre eles está no decorator usado e no tipo de dado que o usuário escolhe. String selects exigem definição explícita de opções. Os outros quatro tipos deixam o Discord preencher a lista automaticamente.

## String selects com opções estáticas

String selects são o tipo mais flexível, porque a lista de opções fica totalmente sob seu controle. Defina essas opções com o decorator empilhável _@SelectOption_, aplicado na classe do componente. Cada opção exige um _label_, que é o texto mostrado, um _value_, que é o valor devolvido ao handler, e pode ter também _description_ e _emoji_. As opções são empilhadas de baixo para cima na ordem dos decorators.

<CodeTabs>
  <Tab label="Componente" language="typescript">
```typescript filename="src/components/selects/language-select.component.ts"
import { StringSelect, SelectOption } from '@spraxium/components';

@StringSelect({
  customId: 'language_picker',
  placeholder: 'Choose a language',
  minValues: 1,
  maxValues: 1,
})
@SelectOption({ label: 'English', value: 'en', description: 'English (US)', emoji: '🇺🇸' })
@SelectOption({ label: 'Português', value: 'pt', description: 'Portuguese (BR)', emoji: '🇧🇷' })
@SelectOption({ label: 'Español', value: 'es', description: 'Spanish', emoji: '🇪🇸' })
export class LanguageSelect {}

````
  </Tab>
  <Tab label="Handler" language="typescript">
```typescript filename="src/components/selects/language-select.handler.ts"
import { StringSelectHandler, Ctx, SelectedValues } from '@spraxium/components';
import type { StringSelectMenuInteraction } from 'discord.js';
import { LanguageSelect } from './language-select.component';

@StringSelectHandler(LanguageSelect)
export class LanguageSelectHandler {
  async handle(
    @Ctx() interaction: StringSelectMenuInteraction,
    @SelectedValues() values: string[],
  ): Promise<void> {
    const language = values[0];
    await interaction.reply({ content: `Language set to ${language}.`, flags: 'Ephemeral' });
  }
}
````

## Opções dinâmicas

Quando a lista de opções depende de dados de runtime, use o callback _dynamicOptions_ no lugar de decorators estáticos _@SelectOption_. Esse callback recebe o objeto _data_ passado para _SelectService.build_ e precisa devolver um array de opções. Esse padrão é comum em selects preenchidos a partir de consultas em banco, respostas de API ou dados específicos do usuário.

```typescript filename="src/components/selects/category-select.component.ts"
import { StringSelect } from '@spraxium/components';

@StringSelect({
  customId: 'category_picker',
  placeholder: 'Select a category',
  dynamicOptions: (data: { categories: Array<{ name: string; id: string }> }) =>
    data.categories.map((cat) => ({
      label: cat.name,
      value: cat.id,
    })),
})
export class CategorySelect {}
```

Na renderização, passe o objeto de dados como segundo argumento para _SelectService.build_. O serviço chama _dynamicOptions_ com esse valor e usa o array retornado para preencher o select menu.

<Callout tone="tip">
  Decorators *@SelectOption* e *dynamicOptions* são mutuamente exclusivos.
  Quando os dois aparecem na mesma classe, o callback dinâmico tem prioridade,
  e as opções estáticas são ignoradas por completo.
</Callout>

## Injeção de parâmetros no handler

Handlers de select usam o mesmo sistema de decorators de parâmetro dos handlers de botão, com dois decorators extras específicos dessa família. *@Selected()* injeta a interação completa do menu de seleção, dando acesso a usuários, cargos, canais ou mentionables já resolvidos. *@SelectedValues()* injeta somente o array `string[]` vindo de *interaction.values*, que é o padrão mais comum em string selects.

```typescript filename="src/components/selects/role-select.handler.ts"
import { RoleSelectHandler, Ctx, Selected } from '@spraxium/components';
import type { RoleSelectMenuInteraction } from 'discord.js';
import { AssignRoleSelect } from './role-select.component';

@RoleSelectHandler(AssignRoleSelect)
export class AssignRoleSelectHandler {
  async handle(
    @Ctx() interaction: RoleSelectMenuInteraction,
    @Selected() selected: RoleSelectMenuInteraction,
  ): Promise<void> {
    const roles = selected.roles;
    const names = roles.map((r) => r.name).join(', ');
    await interaction.reply({ content: `Assigning roles: ${names}`, flags: 'Ephemeral' });
  }
}
````

## Renderização com SelectService

_SelectService_ é o serviço injetável que monta action rows de select menu a partir de classes decoradas. O método _build_ recebe a classe do componente, um argumento opcional de dados para callbacks _dynamicOptions_ e, opcionalmente, um _SpraxiumContext_ para embutir um ID de contexto no _customId_ do menu. O método é assíncrono porque callbacks dinâmicos podem retornar promises.

```typescript filename="src/commands/category.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { SelectService, ContextService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { CategorySelect } from '../components/selects/category-select.component';
import { CategoryCommand } from './category.command';

@SlashCommandHandler(CategoryCommand)
export class CategoryCommandHandler {
  constructor(
    private readonly selects: SelectService,
    private readonly context: ContextService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const categories = await this.fetchCategories(interaction.guildId!);
    const ctx = await this.context.create({ userId: interaction.user.id });
    const row = await this.selects.build(CategorySelect, categories, ctx);

    await interaction.reply({
      content: 'Choose a category:',
      components: [row],
    });
  }

  private async fetchCategories(guildId: string) {
    return [
      { name: 'General', id: 'general' },
      { name: 'Support', id: 'support' },
      { name: 'Feedback', id: 'feedback' },
    ];
  }
}
```

## Alternativa com fluent builder

Em cenários mais programáticos, onde criar uma classe seria exagero, _SelectDefBuilder_ oferece uma API fluente para montar definições de select inline. Esse builder é útil em fluxos dinâmicos, selects temporários ou interfaces geradas por código, onde a abordagem baseada em decorators criaria classes descartáveis demais.

```typescript filename="src/commands/dynamic-select.command.ts"
import { Selects } from '@spraxium/components';

const row = Selects.string('quick_pick')
  .placeholder('Quick selection')
  .minValues(1)
  .maxValues(1)
  .options([
    { label: 'Option A', value: 'a' },
    { label: 'Option B', value: 'b' },
  ])
  .buildRow();
```

O fluent builder produz a mesma action row do discord.js que a abordagem com decorators. A diferença é que ele não participa do sistema de dispatch de handlers, porque não existe classe nem metadado para registrar. Use esse caminho apenas em selects descartáveis, em que o roteamento de handler não é necessário.

## Selects dinâmicos

String selects estáticos definem as opções já no momento da declaração. _@DynamicStringSelect_ quebra essa limitação: você descreve o select uma vez e gera a lista de opções com dados vivos no momento da renderização, como resultados de banco, respostas de API ou qualquer outro valor de runtime. O sistema de payload salva esse conjunto de dados junto do select, então o handler recebe tudo de volta sem precisar consultar a fonte pela segunda vez.

### Como definir um string select dinâmico

Decore uma classe com _@DynamicStringSelect_ e implemente um método estático `render` que receba os dados de payload e devolva um `SelectRenderConfig`. Esse método pode ser síncrono ou assíncrono.

```typescript filename="src/modules/topics/components/topic-select.component.ts"
import { DynamicStringSelect } from '@spraxium/components';
import type { SelectRenderConfig } from '@spraxium/components';
import type { TopicsQuery } from '../topics.data';

@DynamicStringSelect({
  baseId: 'topic-pick',
  placeholder: 'Pick one or more topics',
  minValues: 1,
  maxValues: 3,
  payloadTtl: 600,
})
export class TopicSelect {
  static render(query: TopicsQuery): SelectRenderConfig {
    return {
      options: query.topics.map((t) => ({
        label: t.name,
        value: t.slug,
        description: t.description,
      })),
    };
  }
}
```

### Como renderizar um string select dinâmico

Chame `SelectService.buildDynamic` com a classe do componente e o payload. O Spraxium salva esse payload e embute uma referência a ele no `customId` do select.

```typescript filename="src/modules/topics/handlers/topics-command.handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { SelectService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { TopicsCommand } from '../commands/topics.command';
import { TopicSelect } from '../components/topic-select.component';
import type { TopicsQuery } from '../topics.data';

@SlashCommandHandler(TopicsCommand)
export class TopicsCommandHandler {
  constructor(private readonly selects: SelectService) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const query: TopicsQuery = {
      audience: 'developers',
      topics: await fetchTopics(),
    };

    const row = await this.selects.buildDynamic(TopicSelect, query);
    await interaction.reply({ content: 'Pick topics:', components: [row] });
  }
}
```

### Como tratar a interação

Use _@DynamicSelectHandler_ para vincular um handler a uma classe `@DynamicStringSelect`. O decorator _@SelectPayload()_ injeta o payload armazenado na renderização. Já _@SelectedValues()_ injeta `interaction.values` como `string[]`. Os dois podem aparecer junto de `@Ctx()` e `@PayloadRef()` em qualquer ordem.

```typescript filename="src/modules/topics/handlers/topic-select.handler.ts"
import { Ctx } from '@spraxium/common';
import { DynamicSelectHandler, SelectPayload, SelectedValues } from '@spraxium/components';
import type { StringSelectMenuInteraction } from 'discord.js';
import { TopicSelect } from '../components/topic-select.component';
import type { TopicsQuery } from '../topics.data';

@DynamicSelectHandler(TopicSelect)
export class TopicSelectHandler {
  async handle(
    @Ctx() interaction: StringSelectMenuInteraction,
    @SelectedValues() picks: string[],
    @SelectPayload() query: TopicsQuery,
  ): Promise<void> {
    const picked = query.topics.filter((t) => picks.includes(t.slug));
    await interaction.reply({
      content: `Picked: ${picked.map((t) => t.name).join(', ')}`,
      flags: 'Ephemeral',
    });
  }
}
```

### Codificação inline de parâmetros

Por padrão, _@DynamicStringSelect_ persiste o payload completo em um store com TTL e embute apenas uma referência opaca no custom ID. Para dados pequenos e primitivos — como uma tag de origem, um flag de modo ou um único ID de registro — você pode usar `encoding: 'inline'`. O framework codifica o campo `params` retornado por `render()` diretamente na string do custom ID, eliminando qualquer dependência do store de payload e do TTL. Os dados vivem na mensagem do Discord enquanto essa mensagem existir.

<Callout tone="warning">
  O limite de **100 caracteres** do Discord para custom IDs se aplica a selects
  com codificação inline. O framework lança
  `DynamicSelectInlinePayloadTooLargeError` no momento da renderização se o
  string codificado ultrapassar esse limite. Mantenha os params inline pequenos:
  um ou dois valores curtos. Use o encoding store para qualquer coisa maior.
</Callout>

Note que _@SelectParams()_ substitui _@SelectPayload()_ para selects com codificação inline. Usar _@SelectPayload()_ ou _@PayloadRef()_ em um handler inline causa um erro no bootstrap. O tipo de `params` é inferido do campo `params` retornado por `render()`, então o TypeScript conhece o formato sem nenhum casting manual.

Selects com codificação inline são renderizados com `SelectService.build`, não com `buildDynamic`. O serviço detecta o flag `encoding: 'inline'` automaticamente e roteia para o caminho inline.

## Registro no módulo

Só a classe do handler precisa ser registrada no array _handlers_ de um módulo de feature. Isso vale da mesma forma para os cinco tipos de select. As classes de componente decoradas com _@StringSelect_, _@UserSelect_ e semelhantes existem apenas como metadado e nunca entram em módulo nenhum. O dispatcher lê tudo pela referência de classe armazenada no decorator do handler.

```typescript filename="src/modules/settings/settings.module.ts"
import { Module } from '@spraxium/common';
import { LanguageSelectHandler } from './components/language-select.handler';
import { TargetUserSelectHandler } from './components/user-select.handler';

@Module({
  handlers: [LanguageSelectHandler, TargetUserSelectHandler],
})
export class SettingsModule {}
```
