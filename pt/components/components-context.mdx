## O que é contexto de fluxo

Contexto de fluxo é um contêiner de dados com estado que carrega informações ao longo de interações sequenciais com componentes. Quando uma pessoa clica em um botão, escolhe uma opção e depois envia um modal, cada handler dessa sequência pode precisar de dados que nasceram em etapas anteriores. Sem esse contexto, você teria de codificar estado em strings de _customId_, que são limitadas, jogar dados em um banco externo ou manter mapas globais que tendem a vazar memória.

_SpraxiumContext_ resolve esse problema oferecendo um contêiner tipado, com TTL e, opcionalmente, restrito a um usuário específico. Ele fica armazenado em um adapter plugável e é referenciado por um UUID anexado ao _customId_ do componente. O _ContextService_ cria os contextos, os serviços de componente acoplam esse ID aos elementos renderizados e o dispatcher resolve tudo automaticamente antes de chamar o handler.

O sistema de contexto de fluxo é compartilhado por todos os tipos de componente. Um contexto criado em uma linha de botões pode ser lido mais tarde por um handler de modal no mesmo fluxo. É isso que torna experiências interativas em múltiplas etapas viáveis sem precisar controlar estado na mão.

## Como criar um contexto

Injete _ContextService_ no seu comando ou serviço e chame _create_ com o objeto de dados que você quer carregar ao longo do fluxo. O método devolve um _SpraxiumContext_ com UUID gerado, dados, timestamps e TTL. Depois disso, você passa esse contexto para o método de build do serviço de componente.

```typescript filename="src/commands/setup-wizard.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ContextService, ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { NextStepButton } from '../components/next-step.button';
import { SetupWizardCommand } from './setup-wizard.command';

@SlashCommandHandler(SetupWizardCommand)
export class SetupWizardCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { step: 1, guildId: interaction.guildId, settings: {} },
      { ttl: 600, restrictedTo: interaction.user.id },
    );

    const row = this.buttons.rowWithContext(ctx, NextStepButton);

    await interaction.reply({
      content: 'Welcome to the setup wizard. Click Next to begin.',
      components: [row],
    });
  }
}
```

## Interface SpraxiumContext

O objeto _SpraxiumContext_ carrega tanto os seus dados quanto os metadados operacionais do fluxo. O campo _id_ é o UUID anexado às strings de _customId_ por meio do separador til. O campo _data_ guarda o payload tipado. Já _ttl_ e _expiresAt_ controlam a expiração automática, enquanto _restrictedTo_ limita quais usuários podem interagir com componentes vinculados a esse contexto.

## Como ler o contexto no handler

Use o decorator de parâmetro _@FlowContext()_ no método _handle_ para receber o contexto já resolvido. O dispatcher extrai o ID do contexto a partir do _customId_, busca o valor no adapter de armazenamento, valida expiração e restrições de usuário e injeta o objeto resultante. Se o contexto tiver expirado, ou se a interação vier de um usuário não autorizado, o dispatcher responde com a mensagem de erro configurada e nem chega a chamar o handler.

```typescript filename="src/components/next-step.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { NextStepButton } from './next-step.button';

interface WizardData {
  step: number;
  guildId: string;
  settings: Record<string, unknown>;
}

@ButtonHandler(NextStepButton)
export class NextStepButtonHandler {
  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<WizardData>,
  ): Promise<void> {
    const { step, settings } = ctx.data;
    await interaction.reply({
      content: `You are on step ${step}. Current settings: ${JSON.stringify(settings)}`,
      flags: 'Ephemeral',
    });
  }
}
```

## Como atualizar o contexto

O método _ContextService.update_ aplica um patch nos dados do contexto sem substituir o objeto inteiro. Isso ajuda muito em fluxos de várias etapas, onde cada handler só acrescenta ou ajusta uma parte do estado. O retorno é um booleano informando se a atualização deu certo, ou seja, se o contexto foi encontrado e ainda não tinha expirado.

```typescript filename="src/components/step-two.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import { ContextService } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { StepTwoButton } from './step-two.button';

interface WizardData {
  step: number;
  guildId: string;
  settings: Record<string, unknown>;
}

@ButtonHandler(StepTwoButton)
export class StepTwoButtonHandler {
  constructor(private readonly context: ContextService) {}

  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<WizardData>,
  ): Promise<void> {
    await this.context.update<WizardData>(ctx.id, {
      step: 2,
      settings: { ...ctx.data.settings, language: 'en' },
    });

    await interaction.reply({
      content: 'Step 2 complete. Proceeding to step 3.',
      flags: 'Ephemeral',
    });
  }
}
```

## Como apagar o contexto

Chame _ContextService.delete_ quando o fluxo tiver sido concluído ou cancelado. Isso remove o contexto imediatamente do adapter de armazenamento. Mesmo que a expiração automática já exista por TTL, a exclusão explícita continua sendo uma boa prática em fluxos encerrados normalmente, porque libera espaço e evita a leitura de dados obsoletos em cenários de borda.

```typescript filename="src/components/finish-wizard.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import { ContextService } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { FinishButton } from './finish.button';

@ButtonHandler(FinishButton)
export class FinishWizardHandler {
  constructor(private readonly context: ContextService) {}

  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<unknown>,
  ): Promise<void> {
    await this.context.delete(ctx.id);
    await interaction.reply({ content: 'Setup complete!', flags: 'Ephemeral' });
  }
}
```

### Excluindo contexto de fora de um handler

`ContextService.delete` recebe o ID do contexto como uma string simples, então pode ser chamado a partir de qualquer serviço, handler de comando ou listener - não apenas de dentro de um handler de botão ou modal que receba uma injeção de `@FlowContext()`.

O segredo é persistir o ID do contexto junto aos seus próprios dados de aplicação quando o contexto é criado:

```typescript filename="src/commands/start-onboarding.command-handler.ts"
@SlashCommandHandler(StartOnboardingCommand)
export class StartOnboardingCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
    private readonly db: OnboardingRepository,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { guildId: interaction.guildId!, step: 1 },
      { ttl: 86400, restrictedTo: interaction.user.id },
    );

    // Salve ctx.id no banco de dados para que possa ser cancelado de fora
    await this.db.createSession(interaction.user.id, { contextId: ctx.id });

    const row = this.buttons.rowWithContext(ctx, NextStepButton);
    await interaction.reply({ content: 'Onboarding iniciado!', components: [row] });
  }
}
```

Em seguida, cancele o fluxo a partir de um comando admin ou qualquer outro serviço sem precisar do contexto em escopo:

```typescript filename="src/commands/cancel-onboarding.command-handler.ts"
@SlashCommandHandler(CancelOnboardingCommand)
export class CancelOnboardingCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly db: OnboardingRepository,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const session = await this.db.findActiveSession(interaction.options.getUser('user', true).id);

    if (session?.contextId) {
      // Apaga o contexto - qualquer botão pendente no fluxo
      // receberá agora a mensagem de expiração ao ser clicado.
      await this.context.delete(session.contextId);
    }

    await this.db.removeSession(session.userId);
    await interaction.reply({ content: 'Sessão de onboarding cancelada.', flags: 'Ephemeral' });
  }
}
```

## Comportamento de TTL e expiração

Todo contexto tem um TTL medido em segundos. Quando alguém interage com um componente cujo contexto já expirou, o dispatcher responde com a mensagem configurada em _errorMessages.expired_ e não chama o handler. Contextos expirados não são removidos imediatamente do armazenamento. A limpeza costuma acontecer de forma preguiçosa, no acesso, ou em varreduras periódicas realizadas pelo adapter.

O TTL padrão é definido na configuração de _defineComponents_. Contextos individuais podem sobrescrever esse valor pelo parâmetro _options.ttl_ em _ContextService.create_.

<Callout tone="tip">
  Para interações curtas, como caixas de confirmação, um TTL entre 60 e 120
  segundos costuma ser suficiente. Em assistentes de múltiplas etapas, algo
  entre 600 e 1800 segundos costuma dar uma margem confortável para a pessoa
  concluir o fluxo sem bater numa expiração no meio do caminho.
</Callout>

## Restrições por usuário

A opção _restrictedTo_ limita o acesso ao contexto a um ID de usuário específico. Quando ela está definida, só interações vindas desse usuário são despachadas para o handler. Se outra pessoa clicar no componente, recebe a mensagem configurada em _errorMessages.restricted_. Isso é essencial em fluxos nos quais o componente está visível para todo o canal, mas só deveria poder ser acionado por quem iniciou o comando.

```typescript filename="src/commands/verification.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ContextService, ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { VerifyButton } from '../components/verify.button';
import { VerificationCommand } from './verification.command';

@SlashCommandHandler(VerificationCommand)
export class VerificationCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { userId: interaction.user.id },
      { ttl: 300, restrictedTo: interaction.user.id },
    );

    const row = this.buttons.rowWithContext(ctx, VerifyButton);

    await interaction.reply({
      content: 'Click the button to verify your identity.',
      components: [row],
    });
  }
}
```
