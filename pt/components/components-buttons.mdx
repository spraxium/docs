## Tipos de botão

O Spraxium oferece duas variações de botão, e cada uma resolve um problema diferente. Botões estáticos usam um _customId_ fixo e disparam um handler quando o usuário clica. Botões de link apenas abrem uma URL no navegador e não executam nenhuma lógica no bot.

Nos dois casos, a definição nasce em uma classe decorada e a renderização passa pelo _ButtonService_. Rótulo, estilo, emoji e estado desabilitado ficam descritos no decorator como metadados. Na hora de montar o componente, o renderer lê esses metadados e produz a instância correta de _ButtonBuilder_ do discord.js.

## Botões estáticos

O botão estático é a forma mais direta de criar uma ação clicável. Você decora uma classe com _@Button_ e informa, no mínimo, um _customId_ e um _label_. Esse _customId_ precisa ser único no bot inteiro, porque o dispatcher faz o roteamento comparando o valor recebido com igualdade exata. O campo _style_ segue os estilos de botão do Discord e assume *primary* quando você não informa nada.

<CodeTabs>
  <Tab label="Componente" language="typescript">
```typescript filename="src/components/buttons/confirm.button.ts"
import { Button } from '@spraxium/components';

@Button({
  customId: 'confirm_action',
  label: 'Confirm',
  style: 'success',
  emoji: '✅',
})
export class ConfirmButton {}

````
  </Tab>
  <Tab label="Handler" language="typescript">
```typescript filename="src/components/buttons/confirm.handler.ts"
import { ButtonHandler, Ctx } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import { ConfirmButton } from './confirm.button';

@ButtonHandler(ConfirmButton)
export class ConfirmButtonHandler {
  async handle(@Ctx() interaction: ButtonInteraction): Promise<void> {
    await interaction.reply({ content: 'Action confirmed.', flags: 'Ephemeral' });
  }
}
````

  </Tab>
</CodeTabs>

A classe do handler precisa usar _@ButtonHandler_ e receber a classe do componente como argumento. É isso que cria o vínculo de metadados que o dispatcher resolve durante o bootstrap. No método _handle_, os parâmetros chegam por decorators: _@Ctx()_ injeta o _ButtonInteraction_ bruto e _@FlowContext()_ injeta o contexto quando ele existir.

## Botões de link

Botões de link abrem uma URL no navegador do usuário sem disparar nenhum handler no bot. Eles são úteis quando você quer levar a pessoa para uma documentação, um painel interno ou qualquer ferramenta externa. Como o Discord exige um estilo próprio para links, o decorator _@LinkButton_ elimina _customId_ e _style_ e trabalha com o campo _url_. 

```typescript filename="src/components/buttons/docs-link.button.ts"
import { LinkButton } from '@spraxium/components';

@LinkButton({
  url: 'https://docs.example.com',
  label: 'View Documentation',
  emoji: '📘',
})
export class DocsLinkButton {}
```

Você pode misturar botões de link e botões estáticos na mesma action row. Basta passar todas as classes para _ButtonService.build_, e o renderer escolhe o builder certo para cada uma com base nos metadados.

## Renderização com ButtonService

_ButtonService_ é o serviço injetável que transforma classes decoradas em action rows do discord.js. Ele oferece dois métodos para cenários de renderização diferentes. Como tudo é lido por reflection, você não precisa de configuração extra além das classes decoradas.

  O Discord limita cada action row a cinco botões. O serviço lança um erro se
  você passar mais de cinco classes para *build*. Se precisar de layouts maiores,
  monte múltiplas linhas chamando *build* mais de uma vez e envie cada linha
  separadamente no array *components*.
</Callout>

```typescript filename="src/commands/moderation.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ButtonService, ContextService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { ConfirmButton } from '../components/buttons/confirm.button';
import { CancelButton } from '../components/buttons/cancel.button';
import { DocsLinkButton } from '../components/buttons/docs-link.button';
import { ModerationCommand } from './moderation.command';

@SlashCommandHandler(ModerationCommand)
export class ModerationCommandHandler {
  constructor(
    private readonly buttons: ButtonService,
    private readonly context: ContextService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create({ targetUserId: '123456' });
    const actionRow = this.buttons.rowWithContext(
      ctx,
      ConfirmButton,
      CancelButton,
    );
    const linkRow = this.buttons.build(DocsLinkButton);

    await interaction.reply({
      content: 'Review the moderation action below.',
      components: [actionRow, linkRow],
    });
  }
}
```

## Registro no módulo

Só as classes de handler precisam ser registradas, e elas entram no array _handlers_ do módulo da sua feature. As classes de componente decoradas com _@Button_ ou _@LinkButton_ servem apenas como metadados e nunca são adicionadas a módulo nenhum. O dispatcher lê o _customId_ e a configuração direto da referência de classe armazenada em cada decorator _@ButtonHandler_, sem precisar instanciar o componente pela DI.

```typescript filename="src/modules/moderation/moderation.module.ts"
import { Module } from '@spraxium/common';
import { ConfirmButtonHandler } from './components/confirm.handler';
import { CancelButtonHandler } from './components/cancel.handler';
import { UserBanButtonHandler } from './components/user-ban.handler';

@Module({
  handlers: [ConfirmButtonHandler, CancelButtonHandler, UserBanButtonHandler],
})
export class ModerationModule {}
```

## Botões dinâmicos

Botões estáticos usam um _customId_ fixo, conhecido já na definição da classe. Botões dinâmicos viram essa lógica de cabeça para baixo: o rótulo, o estilo e os dados carregados pelo botão passam a ser calculados a cada renderização, a partir de um payload qualquer. O framework gera o ID automaticamente e embute nele uma referência para o payload armazenado. Quando o usuário clica, o handler recupera esse payload original no store.

O sistema de botões dinâmicos tem três peças: a classe com _@DynamicButton_, que define o componente e sua lógica de renderização; a classe com _@DynamicButtonHandler_, que trata o clique; e o store de payload, que faz a ponte entre uma ponta e outra.

### Como definir um botão dinâmico

Uma classe de botão dinâmico usa _@DynamicButton_ e precisa expor um método estático `render(item)` que retorne um `ButtonRenderConfig`. O _baseId_ da configuração funciona como prefixo no matching das interações recebidas, e o framework acrescenta automaticamente a referência do payload. O _payloadTtl_ é opcional e representa o tempo de vida em segundos. Quando esse tempo expira, cliques posteriores deixam de chegar ao handler. O padrão é 600 segundos, ou 10 minutos.

<CodeTabs>
  <Tab label="Componente" language="typescript">
```typescript filename="src/components/buttons/book-buy.button.ts"
import { DynamicButton } from '@spraxium/components';
import type { ButtonRenderConfig } from '@spraxium/components';

interface Book {
  id: string;
  title: string;
}

@DynamicButton({ baseId: 'buy-book', payloadTtl: 300 })
export class BuyBookButton {
  static render(book: Book): ButtonRenderConfig {
    return {
      label: `Buy "${book.title}"`,
      style: 'success',
    };
  }
}
```
  </Tab>
  <Tab label="Handler" language="typescript">
```typescript filename="src/components/buttons/book-buy.handler.ts"
import { DynamicButtonHandler, Ctx, ButtonPayload, PayloadRef } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { PayloadHandle } from '@spraxium/components';
import { BuyBookButton } from './book-buy.button';

interface Book {
  id: string;
  title: string;
}

@DynamicButtonHandler(BuyBookButton)
export class BuyBookButtonHandler {
  async handle(
    @Ctx() interaction: ButtonInteraction,
    @ButtonPayload() book: Book,
    @PayloadRef() ref: PayloadHandle,
  ): Promise<void> {
    await ref.consume(); // one-shot; prevent double purchase
    await this.orders.create(book.id, interaction.user.id);
    await interaction.reply({ content: `Purchased "${book.title}"!`, flags: 'Ephemeral' });
  }
}
```
  </Tab>
</CodeTabs>

### Como renderizar um botão dinâmico

Para renderizar um único botão dinâmico em uma action row, chame `ButtonService.build` passando a classe do componente e o objeto de payload. O serviço chama `render(item)`, grava o payload no store com TTL e devolve um _ActionRowBuilder_ com o custom ID gerado já embutido.

```typescript filename="src/commands/shop.command-handler.ts"
import { SlashCommandHandler, Ctx } from '@spraxium/common';
import { ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { BuyBookButton } from '../components/buttons/book-buy.button';
import { ShopCommand } from './shop.command';

@SlashCommandHandler(ShopCommand)
export class ShopCommandHandler {
  constructor(private readonly buttons: ButtonService) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const book = await this.catalog.getBook('978-0-7432-7356-5');
    const row = this.buttons.build(BuyBookButton, book);

    await interaction.reply({
      content: `Found **${book.title}**`,
      components: [row],
    });
  }
}
```

Para combinar múltiplos botões dinâmicos de tipos diferentes na mesma linha, use `ButtonService.buildMixedRow`. Ele recebe um array de entradas `{ button, items }` e retorna um único `ActionRowBuilder` junto a um array plano de todos os refs de payload - um por botão store-encoded, na ordem de declaração. Botões inline-encoded não produzem nenhum ref.

```typescript filename="src/commands/open-ticket.command-handler.ts"
import { Ctx, SlashCommandHandler, SlashStringOption } from '@spraxium/common';
import { ButtonService } from '@spraxium/components';
import { type ChatInputCommandInteraction, MessageFlags } from 'discord.js';
import { OpenTicketCommand } from '../commands/open-ticket.command';
import { AssignTicketButton } from '../components/assign-ticket-button.component';
import { CloseTicketButton } from '../components/close-ticket-button.component';
import { TicketsRepository } from '../tickets.repository';

@SlashCommandHandler(OpenTicketCommand)
export class OpenTicketHandler {
  constructor(
    private readonly buttons: ButtonService,
    private readonly tickets: TicketsRepository,
  ) {}

  async handle(
    @Ctx() interaction: ChatInputCommandInteraction,
    @SlashStringOption('subject') subject: string,
  ): Promise<void> {
    const ticket = await this.tickets.create({
      subject,
      openedBy: interaction.user.id,
    });

    // buildMixedRow renderiza os dois botões em uma linha e coleta todos os refs do store.
    // AssignTicketButton é store-encoded (payload persistido, ref rastreado para revogação).
    // CloseTicketButton é inline-encoded (id do ticket no customId, sem ref).
    const [row, refs] = await this.buttons.buildMixedRow([
      { button: AssignTicketButton, items: [ticket] },
      { button: CloseTicketButton, items: [ticket] },
    ]);

    // Persista cada ref para poder revogá-lo quando o ticket for fechado externamente.
    await Promise.all(refs.map((ref) => this.tickets.addAssignRef(ticket.id, ref)));

    await interaction.reply({
      content: [
        `## 🎫 Ticket \`${ticket.id}\``,
        `**Subject:** ${ticket.subject}`,
        `**Opened by:** <@${ticket.openedBy}>`,
      ].join('\n'),
      components: [row],
      flags: MessageFlags.Ephemeral,
    });
  }
}
```

Handlers de botão dinâmico seguem exatamente a mesma regra de registro dos handlers estáticos. Registre só a classe do handler no array _handlers_ do módulo. A classe do componente decorada com _@DynamicButton_ serve apenas como metadado e não precisa aparecer em módulo nenhum.

```typescript filename="src/modules/shop/shop.module.ts"
import { Module } from '@spraxium/common';
import { BuyBookButtonHandler } from './components/book-buy.handler';

  handlers: [BuyBookButtonHandler],

```

<Callout tone="tip">
  _@DynamicStringSelect_ segue a mesma ideia para menus de seleção: você define

### Codificação de parâmetros inline

Por padrão, os botões dinâmicos armazenam seu payload em um store do lado do servidor com TTL e embutem apenas uma referência opaca no custom ID. Essa é a escolha certa para objetos grandes ou complexos.

Para dados pequenos e primitivos - como o ID de um único registro de banco de dados - você pode usar `encoding: 'inline'` em vez disso. O framework codifica os parâmetros diretamente na string do custom ID, eliminando qualquer dependência do store de payload e do TTL completamente. Os dados vivem na mensagem do Discord enquanto essa mensagem existir.

<Callout tone="warning">
  O Discord impõe um limite rígido de **100 caracteres** em custom IDs. O
  framework mede a string codificada no momento da renderização e lança
  `DynamicButtonInlinePayloadTooLargeError` se o resultado ultrapassar esse
  limite. Mantenha os parâmetros inline pequenos: um ou dois IDs curtos ou
  flags. Use a codificação baseada em store para qualquer coisa maior.
</Callout>

Note que `@ButtonParams()` substitui `@ButtonPayload()` para botões com codificação inline. Usar `@ButtonPayload()` ou `@PayloadRef()` em um handler inline causa um erro no bootstrap. O tipo de `params` é inferido do campo `params` retornado por `render()`, então o TypeScript conhece o formato sem nenhum casting manual.

O custom ID codificado para o exemplo acima tem a aparência `approve-suggestion~id=42`. Os valores são codificados em URL para lidar com caracteres especiais. Números e booleanos são convertidos de volta aos seus tipos originais na decodificação.

### Revogando payloads externamente

Quando o payload de um botão dinâmico vive no store, o handler pode consumi-lo com `ref.consume()` depois de tratar o clique. Mas alguns fluxos precisam revogar um payload antes de qualquer clique ocorrer - por exemplo, fechar um ticket via slash command deveria invalidar imediatamente os botões de aprovar/rejeitar no canal do admin.

Injete `ButtonPayloadService` para revogar um ou mais refs de payload a partir de qualquer serviço, handler de comando ou listener.

**Armazenando os refs no momento da renderização**

`ButtonService.buildMixedRow` retorna uma tupla `[ActionRowBuilder, string[]]`. O array de refs contém uma entrada por botão store-encoded na ordem de declaração. Botões inline-encoded não produzem nenhum ref. Salve cada ref no banco de dados para poder revogá-lo depois:

```typescript filename="src/repositories/tickets.repository.ts"
interface TicketRecord {
  id: string;
  subject: string;
  openedBy: string;
  assignRefs: string[]; // refs de payload para todos os botões store-encoded
  status: 'open' | 'closed';
}

export class TicketsRepository {
  async create(data: Pick<TicketRecord, 'subject' | 'openedBy'>): Promise<TicketRecord> {
    // INSERT INTO tickets (...)
    return { id: 'ticket-uuid', assignRefs: [], status: 'open', ...data };
  }

  async addAssignRef(ticketId: string, ref: string): Promise<void> {
    // UPDATE tickets SET assign_refs = JSON_ARRAY_APPEND(assign_refs, '$', ?) WHERE id = ?
  }

  async findOpenById(ticketId: string): Promise<TicketRecord | null> {
    // SELECT ... WHERE id = ? AND status = 'open'
    return null;
  }
}
```

Depois, quando o ticket for fechado de fora de um handler, carregue o registro e revogue todos os refs:

```typescript filename="src/commands/close-ticket.command-handler.ts"
const ticket = await this.tickets.findOpenById(ticketId);

if (ticket?.assignRefs.length) {
  await this.payloads.revokeMany(ticket.assignRefs);
}
```

**Revogando quando o fluxo termina externamente**

```typescript filename="src/commands/close-ticket.command-handler.ts"
import { SlashCommandHandler, Ctx, SlashStringOption } from '@spraxium/common';
import { ButtonPayloadService } from '@spraxium/components';
import { type ChatInputCommandInteraction, MessageFlags } from 'discord.js';
import { CloseTicketCommand } from '../commands/close-ticket.command';
import { TicketsRepository } from '../tickets.repository';

@SlashCommandHandler(CloseTicketCommand)
export class CloseTicketHandler {
  constructor(
    private readonly payloads: ButtonPayloadService,
    private readonly tickets: TicketsRepository,
  ) {}

  async handle(
    @Ctx() interaction: ChatInputCommandInteraction,
    @SlashStringOption('ticket-id') ticketId: string,
  ): Promise<void> {
    const ticket = await this.tickets.findOpenById(ticketId);

    if (!ticket) {
      return interaction.reply({ content: 'Ticket não encontrado ou já fechado.', flags: MessageFlags.Ephemeral });
    }

    // Revogar todos os refs de botões store-encoded - qualquer clique posterior receberá
    // a mensagem de expiração configurada em vez de chegar ao handler.
    if (ticket.assignRefs.length) {
      await this.payloads.revokeMany(ticket.assignRefs);
    }

    await this.tickets.close(ticketId);
    await interaction.reply({ content: `Ticket \`${ticketId}\` fechado.`, flags: MessageFlags.Ephemeral });
  }
}
```
