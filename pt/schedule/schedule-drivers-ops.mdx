## Por que os drivers importam

Em um bot de processo único, cada job agendado roda exatamente uma vez porque existe apenas uma instância do scheduler. Quando você escala para vários shards ou processos, o mesmo job cron pode disparar ao mesmo tempo em cada instância, causando execuções duplicadas. O sistema de drivers resolve isso ao introduzir um mecanismo de lock que garante que apenas uma instância adquira o direito de executar determinado job a cada disparo.

Os drivers são plugáveis. Você configura o driver uma vez na config de schedule, e o framework cuida do restante de forma transparente. Os métodos dos seus jobs não precisam saber qual driver está ativo. Isso significa que você pode desenvolver localmente com _MemoryDriver_ e trocar para _RedisScheduleDriver_ em produção sem mudar nenhum código de serviço.

O modelo de lock é otimista. Quando um job dispara, o driver tenta adquirir um lock usando o nome do job como chave. Se o lock for adquirido, o job roda. Se outro processo já estiver com o lock, o job é silenciosamente ignorado naquela instância. O lock tem um TTL configurável que é liberado automaticamente após a janela esperada de execução.

## Configurando drivers

O _MemoryDriver_ padrão não exige nenhuma configuração. Ele sempre adquire o lock, então cada job roda sempre que dispara. Esse é o comportamento correto para bots de processo único.

Em ambientes distribuídos, troque para _RedisScheduleDriver_, passando as opções de conexão do Redis e um lock TTL opcional. O driver usa `SET key NX EX ttl` para adquirir locks de forma atômica e um script Lua para liberá-los com segurança, sem condições de corrida.

<CodeTabs>
  <Tab label="Memory (default)" language="typescript">
```typescript filename="config/schedule.config.ts"
import { defineSchedule } from '@spraxium/schedule';

export default defineSchedule({
  timezone: 'UTC',
});
```
  </Tab>
  <Tab label="Redis" language="typescript">
```typescript filename="config/schedule.config.ts"
import { defineSchedule, RedisScheduleDriver } from '@spraxium/schedule';

export default defineSchedule({
  timezone: 'UTC',
  defaultLockTtlMs: 30_000,
  driver: new RedisScheduleDriver({
    host: process.env.REDIS_HOST ?? 'localhost',
    port: Number(process.env.REDIS_PORT ?? 6379),
  }),
});
```

</CodeTabs>

## API de ScheduleService

O _ScheduleService_ é um provider injetável que oferece controle total, em runtime, sobre os jobs registrados. Injete-o em qualquer serviço, command handler ou controller para pausar, retomar, destruir ou disparar jobs manualmente pelo nome. O serviço é exportado pelo _ScheduleModule_ global, então fica disponível em todos os módulos sem imports explícitos.

Todo método recebe o _name_ do job, conforme definido nas opções do decorator. Se você não definir um nome explícito, o framework usará um nome gerado a partir da classe e do método. Nomes explícitos são fortemente recomendados para qualquer job que você pretenda administrar em runtime.

## Usando ScheduleService em um command

Um caso de uso prático para _ScheduleService_ é criar comandos administrativos que permitem a donos de guild ou administradores do bot controlar tarefas em segundo plano sem reiniciar o bot. O exemplo abaixo mostra um prefix command handler que pausa ou retoma um job pelo nome. O mesmo padrão funciona com slash commands ou endpoints de dashboard.

```typescript filename="src/modules/admin/handlers/schedule-admin.handler.ts"
import { Ctx, PrefixArg, PrefixCommandHandler } from '@spraxium/common';
import { ScheduleService } from '@spraxium/schedule';
import type { Message } from 'discord.js';
import { ScheduleAdminCommand } from '../commands/schedule-admin.command';

@PrefixCommandHandler(ScheduleAdminCommand)
export class ScheduleAdminHandler {
  constructor(private readonly scheduleService: ScheduleService) {}

  async handle(
    @Ctx() message: Message,
    @PrefixArg('action') action: string,
    @PrefixArg('jobName') jobName: string,
  ): Promise<void> {
    const job = this.scheduleService.get(jobName);
    if (!job) {
      await message.reply(`Job \`${jobName}\` not found.`);
      return;
    }

    if (action === 'pause') {
      this.scheduleService.pause(jobName);
      await message.reply(`Job \`${jobName}\` paused.`);
    } else if (action === 'resume') {
      this.scheduleService.resume(jobName);
      await message.reply(`Job \`${jobName}\` resumed.`);
    } else if (action === 'run') {
      await this.scheduleService.runNow(jobName);
      await message.reply(`Job \`${jobName}\` triggered manually.`);
    }
  }
}
```
