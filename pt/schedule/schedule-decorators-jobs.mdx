## @Cron e @Interval

Os dois tipos de job recorrente cobrem a grande maioria das necessidades de agendamento. _@Cron_ roda em agendas baseadas em calendário usando expressões cron padrão de 5 ou 6 campos. _@Interval_ se repete em um deslocamento fixo em milissegundos a partir da execução anterior. Ambos os decorators aceitam um objeto de opções para nomear, desabilitar e controlar se o job deve rodar imediatamente na inicialização.

A opção _name_ é importante porque ela é a chave usada para pausar, retomar ou destruir o job em runtime por meio do _ScheduleService_. Se você omitir o nome, o framework gera um automaticamente a partir da classe e do método, mas nomes explícitos são mais fáceis de referenciar em comandos administrativos e dashboards. A opção _disabled_ permite definir o job no código sem iniciá-lo, o que é útil com feature flags.

O decorator _@Cron_ também aceita a opção _timezone_, que sobrescreve o fuso horário global definido na config de schedule. Isso é útil quando um único bot atende comunidades em fusos diferentes e você precisa que um resumo diário seja enviado às 9h no horário local de cada região.

<CodeTabs>
  <Tab label="Cron job" language="typescript">
```typescript filename="src/modules/tasks/services/cleanup.service.ts"
import { Injectable } from '@spraxium/common';
import { Cron, CronExpression } from '@spraxium/schedule';

@Injectable()
export class CleanupService {
  @Cron(CronExpression.EVERY_DAY_AT_MIDNIGHT, {
    name: 'cleanup-expired-warnings',
    timezone: 'UTC',
  })
  async cleanExpiredWarnings(): Promise<void> {
    // Remove warnings older than 30 days
  }
}

````
  </Tab>
  <Tab label="Interval job" language="typescript">
```typescript filename="src/modules/tasks/services/sync.service.ts"
import { Injectable } from '@spraxium/common';
import { Interval, IntervalExpression } from '@spraxium/schedule';

@Injectable()
export class SyncService {
  @Interval(IntervalExpression.EVERY_5_MINUTES, {
    name: 'sync-member-count',
  })
  async syncMemberCount(): Promise<void> {
    // Update cached member counts from the API
  }
}
````

## @Timeout e @AfterOnline

Os dois tipos de job de execução única cobrem padrões de inicialização adiada. _@Timeout_ dispara uma vez após um atraso fixo contado desde o boot da aplicação. _@AfterOnline_ dispara uma vez depois que o cliente do Discord emite o evento _ready_, com a possibilidade de um atraso adicional opcional. Nenhum dos dois se repete: eles executam exatamente uma vez e depois o framework os remove do registro.

A diferença principal entre _@Timeout_ e _@AfterOnline_ está no ponto inicial da contagem do atraso. Um timeout começa a contar no momento em que a aplicação dá boot, o que significa que o cliente do Discord talvez ainda não esteja conectado. Um job after-online começa a contar a partir do evento _ready_, garantindo que o client, as guilds e os canais estejam disponíveis quando o método rodar. Use _@AfterOnline_ sempre que o job precisar chamar métodos da API do Discord.

Os dois decorators aceitam as mesmas opções _name_ e _disabled_. O decorator _@Timeout_ não oferece suporte a _runOnInit_ porque, por definição, é um timer de execução única que sempre roda apenas uma vez. Em ambos os casos, o valor do atraso é dado em milissegundos.

<CodeTabs>
  <Tab label="Timeout" language="typescript">
```typescript filename="src/modules/tasks/services/init.service.ts"
import { Injectable } from '@spraxium/common';
import { Timeout, TimeoutExpression } from '@spraxium/schedule';

@Injectable()
export class InitService {
  @Timeout(TimeoutExpression.AFTER_30_SECONDS, {
    name: 'deferred-cache-warmup',
  })
  async warmCache(): Promise<void> {
    // Populate caches 30 seconds after boot
  }
}

````
  </Tab>
  <Tab label="After online" language="typescript">
```typescript filename="src/modules/tasks/services/welcome.service.ts"
import { Injectable } from '@spraxium/common';
import { AfterOnline } from '@spraxium/schedule';

@Injectable()
export class WelcomeService {
  @AfterOnline(5000, {
    name: 'post-online-announcement',
  })
  async announceOnline(): Promise<void> {
    // Send 'bot is online' message 5 seconds after ready
  }
}
````

  </Tab>
</CodeTabs>

## @RunOnce

_@RunOnce_ agenda um método para rodar exatamente uma vez em um ponto absoluto no futuro. Ao contrário dos decorators recorrentes e de atraso relativo, aqui você passa uma instância de `Date` em vez de uma duração ou de uma expressão cron. Depois que o job dispara, o framework o remove automaticamente do registro, e ele deixa de aparecer em _ScheduleService.getAll()_.

Se a data informada já estiver no passado quando o bot iniciar, o job será registrado, mas nunca vai disparar. O framework emite um aviso no log para deixar a configuração incorreta visível, mas não lança erro nem impede a inicialização.

<CodeTabs>
  <Tab label="Fixed date" language="typescript">
```typescript filename="src/modules/tasks/services/launch.service.ts"
import { Injectable } from '@spraxium/common';
import { RunOnce } from '@spraxium/schedule';

const LAUNCH_DATE = new Date('2026-06-01T20:00:00Z');

@Injectable()
export class LaunchService {
  @RunOnce(LAUNCH_DATE, { name: 'product-launch-ping' })
  async pingLaunch(): Promise<void> {
    // Fires once at 20:00 UTC on 2026-06-01
    await this.notifier.ping();
  }
}
```
  </Tab>
  <Tab label="Dynamic date" language="typescript">
```typescript filename="src/modules/tasks/services/event.service.ts"
import { Injectable } from '@spraxium/common';
import { RunOnce } from '@spraxium/schedule';

@Injectable()
export class EventService {
  @RunOnce(new Date('2026-12-31T23:00:00Z'), { name: 'new-year-announcement' })
  async sendNewYearMessage(): Promise<void> {
    await this.channel.send('🎉 Happy New Year!');
  }
}
```
  </Tab>
</CodeTabs>

<Callout tone="warning">
  _@RunOnce_ exige uma instância válida de Date. Passar uma string de data ou
  uma data inválida lança uma ConfigurationException na inicialização, antes
  mesmo de o bot se conectar ao Discord.
</Callout>

## Helpers em enum

O módulo de schedule fornece três objetos no estilo enum com constantes nomeadas para valores de tempo comuns. Usar essas constantes deixa o código mais legível do que trabalhar com números crus e strings cron. Cada helper cobre os valores mais frequentes no contexto de bots de Discord.

_CronExpression_ oferece mais de 45 presets, como `EVERY_DAY_AT_MIDNIGHT`, `EVERY_HOUR`, `EVERY_MONDAY_AT_MIDNIGHT` e `EVERY_5_MINUTES`. _IntervalExpression_ oferece mais de 25 presets em milissegundos, como `EVERY_MINUTE`, `EVERY_5_MINUTES` e `EVERY_HOUR`. _TimeoutExpression_ oferece mais de 20 presets, como `AFTER_10_SECONDS`, `AFTER_5_MINUTES` e `AFTER_1_HOUR`.

Você sempre pode passar valores brutos em vez das constantes do enum. Esses helpers são apenas reexports de conveniência para melhorar a legibilidade e evitar erros de digitação em expressões cron.

```typescript filename="src/modules/tasks/services/example.service.ts"
import { Injectable } from '@spraxium/common';
import {
  Cron,
  CronExpression,
  Interval,
  IntervalExpression,
} from '@spraxium/schedule';

@Injectable()
export class ExampleService {
  @Cron(CronExpression.EVERY_WEEKDAY)
  async weekdayReport(): Promise<void> {}

  @Cron('0 */6 * * *')
  async customCron(): Promise<void> {}

  @Interval(IntervalExpression.EVERY_30_SECONDS)
  async frequentPoll(): Promise<void> {}
}
```
