## Por que preferências de locale precisam de uma store persistente

_I18nService.tUser()_ resolve o locale de uma pessoa seguindo uma cadeia de prioridade: preferência do usuário, depois preferência da guild e, por fim, o locale padrão configurado. Para essa cadeia continuar funcionando depois de um restart do bot, alguém precisa lembrar essas preferências. A store é exatamente esse componente. Ela é a interface responsável por persistir e recuperar a escolha de locale feita por usuários e guilds.

O motivo de a store existir como peça separada e intercambiável, em vez de ser uma estrutura em memória hardcoded, é simples: preferências de locale têm o mesmo requisito de persistência de qualquer outra configuração visível para a pessoa usuária. Quem escolhe português hoje espera continuar em português amanhã, mesmo depois de o bot reiniciar. Isso exige um backend que sobreviva a reinícios de processo. O backend ideal depende do que o bot já usa para persistência no restante do projeto, e é por isso que a store é uma interface, não uma implementação fixa.

## Como o I18nStoreRegistry funciona

_I18nStoreRegistry_ é uma classe estática que guarda a referência da store ativa. O lifecycle de i18n sempre chama _I18nStoreRegistry.get()_ durante o boot para recuperar a store, exista ou não uma implementação customizada registrada. Se nenhuma store customizada tiver sido definida, o registry cria e devolve automaticamente uma instância de _MemoryStore_. Não há erro e nenhuma configuração extra é exigida para o uso básico.

O ponto mais importante desse desenho é que o registro da store é **independente do objeto de configuração do plugin**. Você chama _I18nStoreRegistry.set(yourStore)_ em qualquer momento anterior à execução do lifecycle de i18n. Pode ser no bootstrap principal, em um hook customizado de lifecycle ou em qualquer outro ponto da sequência de startup. O registry mantém essa referência até o bot desligar ou até _reset()_ ser chamado.

## Registrando uma store customizada

```typescript filename="src/main.ts"
import { I18nStoreRegistry } from '@spraxium/i18n';
import { IntentPreset, SpraxiumFactory } from '@spraxium/core';
import { DrizzleLocaleStore } from './stores/drizzle-locale.store';
import { db } from './database/connection';

async function main(): Promise<void> {
  I18nStoreRegistry.set(new DrizzleLocaleStore(db));

  const app = await SpraxiumFactory.create({
    token: process.env.DISCORD_TOKEN!,
  });

  app.intents(IntentPreset.Standard);

  await app.listen();
}

main();
```

A store é registrada logo no topo de _main_, antes de _SpraxiumFactory.create()_ ser chamado. Isso garante que ela já esteja disponível quando o lifecycle de i18n rodar. Colocar esse registro no bootstrap principal também torna a dependência explícita e fácil de localizar.

## Implementando uma store customizada

Qualquer classe que implemente _I18nStore_ é uma store válida. A interface exige cinco métodos. Os exemplos abaixo mostram implementações equivalentes usando bibliotecas de banco bastante comuns, para que você adapte o padrão ao ORM já usado no projeto.

<CodeTabs>
  <Tab label="Drizzle ORM" language="typescript">
```typescript filename="stores/drizzle-locale.store.ts"
import type { I18nStore } from '@spraxium/i18n';
import { eq } from 'drizzle-orm';
import { localePreferences, guildLocalePreferences } from '../db/schema';

export class DrizzleLocaleStore implements I18nStore {
  constructor(private readonly db: DrizzleDatabase) {}

  async init(): Promise<void> {
    // Run migrations, create tables, or perform connection checks here.
    // Called once at boot by I18nLifecycle, not on every translation request.
  }

  async getUser(userId: string): Promise<string | undefined> {
    const row = await this.db
      .select()
      .from(localePreferences)
      .where(eq(localePreferences.userId, userId))
      .limit(1);
    return row[0]?.locale ?? undefined;
  }

  async setUser(userId: string, locale: string): Promise<void> {
    await this.db
      .insert(localePreferences)
      .values({ userId, locale })
      .onConflictDoUpdate({ target: localePreferences.userId, set: { locale } });
  }

  async getGuild(guildId: string): Promise<string | undefined> {
    const row = await this.db
      .select()
      .from(guildLocalePreferences)
      .where(eq(guildLocalePreferences.guildId, guildId))
      .limit(1);
    return row[0]?.locale ?? undefined;
  }

  async setGuild(guildId: string, locale: string): Promise<void> {
    await this.db
      .insert(guildLocalePreferences)
      .values({ guildId, locale })
      .onConflictDoUpdate({ target: guildLocalePreferences.guildId, set: { locale } });
  }
}
````

```typescript filename="stores/prisma-locale.store.ts"
import type { I18nStore } from '@spraxium/i18n';
import type { PrismaClient } from '@prisma/client';

export class PrismaLocaleStore implements I18nStore {
  constructor(private readonly prisma: PrismaClient) {}

  async init(): Promise<void> {
    // Optionally verify connection or run a lightweight query here.
    // Called once at boot by I18nLifecycle, not on every translation request.
  }

  async getUser(userId: string): Promise<string | undefined> {
    const record = await this.prisma.userLocale.findUnique({ where: { userId } });
    return record?.locale ?? undefined;
  }

  async setUser(userId: string, locale: string): Promise<void> {
    await this.prisma.userLocale.upsert({
      where:  { userId },
      create: { userId, locale },
      update: { locale },
    });
  }

  async getGuild(guildId: string): Promise<string | undefined> {
    const record = await this.prisma.guildLocale.findUnique({ where: { guildId } });
    return record?.locale ?? undefined;
  }

  async setGuild(guildId: string, locale: string): Promise<void> {
    await this.prisma.guildLocale.upsert({
      where:  { guildId },
      create: { guildId, locale },
      update: { locale },
    });
  }
}
````

```typescript filename="stores/typeorm-locale.store.ts"
import type { I18nStore } from '@spraxium/i18n';
import type { Repository, DataSource } from 'typeorm';
import { Entity, PrimaryColumn, Column } from 'typeorm';

@Entity('user_locales')
class UserLocale {
  @PrimaryColumn()
  userId!: string;
  @Column()
  locale!: string;
}

@Entity('guild_locales')
class GuildLocale {
  @PrimaryColumn()
  guildId!: string;
  @Column()
  locale!: string;
}

export class TypeORMLocaleStore implements I18nStore {
  private users!: Repository<UserLocale>;
  private guilds!: Repository<GuildLocale>;

  constructor(private readonly dataSource: DataSource) {}

  async init(): Promise<void> {
    await this.dataSource.synchronize();
    this.users = this.dataSource.getRepository(UserLocale);
    this.guilds = this.dataSource.getRepository(GuildLocale);
  }

  async getUser(userId: string): Promise<string | undefined> {
    const record = await this.users.findOne({ where: { userId } });
    return record?.locale ?? undefined;
  }

  async setUser(userId: string, locale: string): Promise<void> {
    await this.users.upsert({ userId, locale }, ['userId']);
  }

  async getGuild(guildId: string): Promise<string | undefined> {
    const record = await this.guilds.findOne({ where: { guildId } });
    return record?.locale ?? undefined;
  }

  async setGuild(guildId: string, locale: string): Promise<void> {
    await this.guilds.upsert({ guildId, locale }, ['guildId']);
  }
}
````

## Usando a MemoryStore embutida no desenvolvimento

*MemoryStore* é o fallback padrão. Ela guarda preferências em dois *Map*s criados do zero a cada início do processo e perdidos quando ele termina. Não exige setup, banco nem variável de ambiente. Para desenvolvimento local, ou para bots em que preferência de locale não seja uma funcionalidade relevante, *MemoryStore* é a escolha certa: o sistema funciona normalmente, só que as preferências não sobrevivem a reinícios.

Você nunca precisa registrar *MemoryStore* explicitamente. Ela entra automaticamente quando nenhuma store customizada for registrada. Se quiser deixar isso explícito por clareza de documentação ou em testes, ainda assim pode chamar *I18nStoreRegistry.set(new MemoryStore())* em qualquer ponto do startup.

## Um comando de troca de locale que grava na store

```typescript filename="locale.handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { I18nService } from '@spraxium/i18n';
import type { ChatInputCommandInteraction } from 'discord.js';
import { LocaleCommand } from '../commands/locale.command';

@SlashCommandHandler(LocaleCommand)
export class LocaleHandler {
  constructor(private readonly i18n: I18nService) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const locale = interaction.options.getString('locale', true);
    const userId = interaction.user.id;

    await this.i18n.setUserLocale(userId, locale);

    const confirmation = await this.i18n.tUser(
      userId,
      'commands.locale.changed',
      { locale },
    );

    await interaction.reply({ content: confirmation, flags: 'Ephemeral' });
  }
}
````

_I18nService.setUserLocale()_ delega diretamente para _store.setUser()_. A próxima chamada de _tUser()_ desse mesmo usuário já será resolvida no novo locale. Não existe cache para invalidar porque a cadeia de prioridade sempre consulta a store a cada chamada.

## Resetando a store em testes

Como _I18nStoreRegistry_ é estático, estado pode vazar de um teste para outro. Use _reset()_ nos hooks de teardown para manter os casos isolados:

<CodeTabs>
  <Tab label="Vitest" language="typescript">
```typescript filename="test/i18n.test.ts"
import { I18nStoreRegistry, MemoryStore } from '@spraxium/i18n';

beforeEach(() => {
  I18nStoreRegistry.set(new MemoryStore());
});

afterEach(() => {
  I18nStoreRegistry.reset();
});

````
