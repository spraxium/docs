## Configuring the logger

Keep logger configuration in a dedicated _config/logger.config.ts_ file and reference it from _spraxium.config.ts_. That keeps the root config readable and makes it obvious where log levels, masking, timestamps, and Discord forwarding are defined.

The framework applies this configuration during bootstrap, before your providers begin emitting logs. In practice, that means the first line your bot writes already uses the configured timestamp format, custom levels, and transports.

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  levels: [
    { name: 'audit', color: 'blueBright' },
    { name: 'payment', color: 'greenBright' },
  ],
  maskTokens: true,
  discord: {
    type: 'channel',
    channelId: '1234567890',
    levels: ['error', 'warn', 'command'],
  },
};
```

```typescript filename="spraxium.config.ts"
import { defineConfig } from '@spraxium/core';
import { loggerConfig } from './config/logger.config';

export default defineConfig((_env) => ({
  logger: loggerConfig,
}));
```

The _levels_ array registers custom log levels with their console colors. Those levels become available through _Logger.extend_ and are understood by both built-in transports. The _maskTokens_ flag controls the _TokenMasker_, which is enabled by default. Only turn it off in tightly controlled local debugging sessions.

## The Discord transport

The Discord transport forwards selected log entries as embeds to Discord. It only sends levels listed in its own _levels_ array, so you can keep high-volume operational logs in the terminal while forwarding warnings, errors, or command audits to a shared channel.

Two delivery modes are available. In _channel_ mode, the transport uses the bot client itself to look up the channel and send embeds. In _webhook_ mode, it sends HTTP requests to a webhook URL, which is useful when the target destination is operationally separate from the bot runtime.

In channel mode, the transport queues messages that arrive before the client is ready. Once the client emits _ready_, the queue flushes automatically. The queue has a maximum size of 100 entries to avoid memory growth during long startup sequences.

The transport also deduplicates entries. If the same level, context, and message are sent within one second, the second send is suppressed. This protects operational channels from accidental duplicate bursts caused by retry paths or overlapping event handlers.

## Custom embed templates

By default, Discord embeds use the level as the title, the message as the description, a matching color, and an ISO timestamp. Override this with a custom _embed_ template when you want a more operational layout, for example including shard, guild, or metadata fields in predictable positions.

````typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  discord: {
    type: 'channel',
    channelId: '1234567890123456789',
    levels: ['error', 'warn', 'command'],
    embed: {
      title: '{{level}} Log',
      description: "```\n{{message}}\n```",
      color: 0xff6b6b,
      timestamp: true,
      footer: { text: "Shard {{shard}} \u00b7 {{date}} {{time}}" },
      fields: [
        { name: 'Context', value: '{{context}}', inline: true },
        { name: 'Level', value: '{{level}}', inline: true },
      ],
    },
  },
};
````

The available placeholder variables are resolved from the log entry at send time. The _shard_ variable shows the shard ID when the bot is sharded, or "N/A" in a single process. Metadata passed through _log_ is also exposed as placeholders, which is what makes command and audit logs especially useful in Discord.

## Command logging

The _CommandLogger_ service automatically logs every slash command execution. It binds to the client's _interactionCreate_ event and captures the command name, user tag, user ID, guild name, guild ID, and channel ID. Each execution emits a log entry at the _command_ level with structured metadata that you can reuse in embed templates.

The standard way to enable command logging is through _spraxium.config.ts_. Set _commandLogging_ to _true_ inside the logger block and the framework calls _CommandLogger.bind_ automatically during client wiring. This is the preferred setup for most bots because it stays inside the normal framework lifecycle.

```typescript filename="config/logger.config.ts"
import type { SpraxiumLoggerConfig } from '@spraxium/logger';

export const loggerConfig: SpraxiumLoggerConfig = {
  maskTokens: true,
  commandLogging: true,
  discord: {
    type: 'channel',
    channelId: '1234567890123456789',
    levels: ['command'],
    embed: {
      title: 'Command Executed',
      description: '`/{{command}}` by **{{user}}**',
      timestamp: true,
      footer: { text: '{{guild}} ({{guildId}})' },
    },
  },
};
```

If you are using the logger outside the framework or need to bind command logging manually, call _CommandLogger.bind_ directly with the Discord client after it is ready. The command, user, guild, and channel metadata then become available to your embed template.

```typescript filename="src/main.ts"
import { CommandLogger } from '@spraxium/logger';

// Call after the client is ready
CommandLogger.bind(client);
```

## Custom transports

Create a custom transport when console output and Discord delivery are not enough, for example when writing to files, external observability stacks, or internal event buses. A transport implements _LogTransport_, exposes a _name_, and provides a _log_ method that receives a _LogEntry_.

Transport failures are isolated from the rest of the app. If a transport throws or rejects, the logger swallows that failure so logging never becomes a single point of failure for your bot runtime.

```typescript filename="src/transports/file.transport.ts"
import { appendFileSync } from 'node:fs';
import type { LogEntry, LogTransport } from '@spraxium/logger';

export class FileTransport implements LogTransport {
  readonly name = 'file';

  constructor(private readonly path: string) {}

  log(entry: LogEntry): void {
    const line = `[${entry.timestamp.toISOString()}] ${entry.level.toUpperCase()} ${entry.context ?? ''} ${entry.message}\n`;
    appendFileSync(this.path, line);
  }
}
```

Register the transport with _Logger.addTransport_. If a transport with the same name already exists, it is replaced. You can remove a transport by name with _Logger.removeTransport_. The _ConsoleTransport_ is always registered by default and uses the name `"console"`.

```typescript filename="src/main.ts"
import { Logger } from '@spraxium/logger';
import { FileTransport } from './transports/file.transport';

Logger.addTransport(new FileTransport('./logs/bot.log'));
```

If your transport needs the Discord client (for example to look up channel names or resolve guild data), implement the _ClientAwareTransport_ interface instead. It adds a _setClient_ method that the framework calls automatically when the client is ready. The built-in _DiscordTransport_ uses this interface internally.
