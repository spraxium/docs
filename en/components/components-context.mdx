## What is flow context

Flow context is a stateful data container that threads information across sequential component interactions. When a user clicks a button, selects an option, and then submits a modal, each handler in that sequence may need access to data from previous steps. Without flow context, you would need to encode state into _customId_ strings (limited to 100 characters), store data in an external database, or use global maps that leak memory.

_SpraxiumContext_ solves this by providing a typed, TTL-bound, optionally user-restricted data container that is stored in a pluggable adapter and referenced by a UUID appended to the component's _customId_. The _ContextService_ creates contexts, the component services attach context IDs to rendered components, and the dispatcher resolves contexts automatically before invoking handlers.

The flow context system is shared across all component types. A context created for a button row can be read by a modal handler triggered later in the same flow. This cross-component threading is what makes multi-step interactive experiences possible without manual state management.

## Creating a context

Inject _ContextService_ into your command or service and call _create_ with the data object you want to thread through the flow. The method returns a _SpraxiumContext_ with a generated UUID, the data, timestamps, and the TTL. You then pass this context to the component service's build method.

```typescript filename="src/commands/setup-wizard.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ContextService, ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { NextStepButton } from '../components/next-step.button';
import { SetupWizardCommand } from './setup-wizard.command';

@SlashCommandHandler(SetupWizardCommand)
export class SetupWizardCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { step: 1, guildId: interaction.guildId, settings: {} },
      { ttl: 600, restrictedTo: interaction.user.id },
    );

    const row = this.buttons.rowWithContext(ctx, NextStepButton);

    await interaction.reply({
      content: 'Welcome to the setup wizard. Click Next to begin.',
      components: [row],
    });
  }
}
```

## SpraxiumContext interface

The _SpraxiumContext_ object carries both your custom data and operational metadata. The _id_ is a UUID that gets appended to _customId_ strings via the tilde separator. The _data_ field holds your typed payload. The _ttl_ and _expiresAt_ fields control automatic expiration, and _restrictedTo_ limits which user can interact with components carrying this context.

## Reading context in handlers

Use the _@FlowContext()_ parameter decorator in your handler's _handle_ method to receive the resolved context. The dispatcher extracts the context ID from the _customId_, retrieves the context from the storage adapter, validates expiration and user restrictions, and injects the resolved object. If the context has expired or the user is restricted, the dispatcher replies with the configured error message and does not invoke the handler.

```typescript filename="src/components/next-step.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { NextStepButton } from './next-step.button';

interface WizardData {
  step: number;
  guildId: string;
  settings: Record<string, unknown>;
}

@ButtonHandler(NextStepButton)
export class NextStepButtonHandler {
  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<WizardData>,
  ): Promise<void> {
    const { step, settings } = ctx.data;
    await interaction.reply({
      content: `You are on step ${step}. Current settings: ${JSON.stringify(settings)}`,
      flags: 'Ephemeral',
    });
  }
}
```

## Updating context

The _ContextService.update_ method patches the context data without replacing the entire object. This is useful in multi-step flows where each handler adds or modifies a subset of the data. The method returns a boolean indicating whether the update succeeded (context found and not expired).

```typescript filename="src/components/step-two.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import { ContextService } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { StepTwoButton } from './step-two.button';

interface WizardData {
  step: number;
  guildId: string;
  settings: Record<string, unknown>;
}

@ButtonHandler(StepTwoButton)
export class StepTwoButtonHandler {
  constructor(private readonly context: ContextService) {}

  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<WizardData>,
  ): Promise<void> {
    await this.context.update<WizardData>(ctx.id, {
      step: 2,
      settings: { ...ctx.data.settings, language: 'en' },
    });

    await interaction.reply({
      content: 'Step 2 complete. Proceeding to step 3.',
      flags: 'Ephemeral',
    });
  }
}
```

## Deleting context

Call _ContextService.delete_ when the flow is complete or cancelled. This immediately removes the context from the storage adapter. While contexts expire automatically based on TTL, explicit deletion is good practice for flows that complete normally, as it frees storage and prevents stale data from being read in edge cases.

```typescript filename="src/components/finish-wizard.handler.ts"
import { ButtonHandler, Ctx, FlowContext } from '@spraxium/components';
import { ContextService } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { SpraxiumContext } from '@spraxium/components';
import { FinishButton } from './finish.button';

@ButtonHandler(FinishButton)
export class FinishWizardHandler {
  constructor(private readonly context: ContextService) {}

  async handle(
    @Ctx() interaction: ButtonInteraction,
    @FlowContext() ctx: SpraxiumContext<unknown>,
  ): Promise<void> {
    await this.context.delete(ctx.id);
    await interaction.reply({ content: 'Setup complete!', flags: 'Ephemeral' });
  }
}
```

### Deleting context from outside a handler

`ContextService.delete` accepts the context ID as a plain string, so it can be called from any service, command handler, or listener - not only from inside a button or modal handler that receives a `@FlowContext()` injection.

The key is to persist the context ID alongside your own application data when the context is created:

```typescript filename="src/commands/start-onboarding.command-handler.ts"
@SlashCommandHandler(StartOnboardingCommand)
export class StartOnboardingCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
    private readonly db: OnboardingRepository,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { guildId: interaction.guildId!, step: 1 },
      { ttl: 86400, restrictedTo: interaction.user.id },
    );

    // Store ctx.id in your database so it can be cancelled from outside
    await this.db.createSession(interaction.user.id, { contextId: ctx.id });

    const row = this.buttons.rowWithContext(ctx, NextStepButton);
    await interaction.reply({ content: 'Onboarding started!', components: [row] });
  }
}
```

Then cancel the flow from an admin command or any other service without needing the context in scope:

```typescript filename="src/commands/cancel-onboarding.command-handler.ts"
@SlashCommandHandler(CancelOnboardingCommand)
export class CancelOnboardingCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly db: OnboardingRepository,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const session = await this.db.findActiveSession(interaction.options.getUser('user', true).id);

    if (session?.contextId) {
      // Delete the context - any pending buttons in the flow
      // will now receive the expired message when clicked.
      await this.context.delete(session.contextId);
    }

    await this.db.removeSession(session.userId);
    await interaction.reply({ content: 'Onboarding session cancelled.', flags: 'Ephemeral' });
  }
}
```

## TTL and expiration behavior

Every context has a TTL measured in seconds. When a user interacts with a component whose context has expired, the dispatcher replies with the configured _errorMessages.expired_ message and does not invoke the handler. Expired contexts are not deleted immediately from storage; they are cleaned up lazily when accessed or during periodic sweeps by the storage adapter.

The default TTL is set in the _defineComponents_ configuration. Individual contexts can override it through the _options.ttl_ parameter in _ContextService.create_.

<Callout tone="tip">
  For short interactions like confirmation dialogs, a TTL of 60 to 120 seconds
  is appropriate. For multi-step wizards, 600 to 1800 seconds provides a
  comfortable window for users to complete the flow without hitting an
  expiration mid-interaction.
</Callout>

## User restrictions

The _restrictedTo_ option limits context access to a specific user ID. When set, only interactions from that user ID are dispatched to the handler. Other users who click the component receive the configured _errorMessages.restricted_ message. This is essential for flows where the component is visible to everyone in a channel but should only be actionable by the user who initiated the command.

```typescript filename="src/commands/verification.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ContextService, ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { VerifyButton } from '../components/verify.button';
import { VerificationCommand } from './verification.command';

@SlashCommandHandler(VerificationCommand)
export class VerificationCommandHandler {
  constructor(
    private readonly context: ContextService,
    private readonly buttons: ButtonService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create(
      { userId: interaction.user.id },
      { ttl: 300, restrictedTo: interaction.user.id },
    );

    const row = this.buttons.rowWithContext(ctx, VerifyButton);

    await interaction.reply({
      content: 'Click the button to verify your identity.',
      components: [row],
    });
  }
}
```
