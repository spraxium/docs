## Button types

Spraxium provides two button variants, each with its own decorator and use case. Static buttons have a fixed _customId_ and fire a handler when clicked. Link buttons open a URL in the user's browser and do not fire any handler.

Both types are defined as decorated classes and rendered through _ButtonService_. The visual properties, label, style, emoji, and disabled state, are configured in the decorator and stored as metadata. The renderer reads this metadata at build time and produces the appropriate discord.js _ButtonBuilder_ instance.

## Static buttons

A static button is the simplest interactive component. You decorate a class with _@Button_, providing a _customId_ and a _label_ at minimum. The _customId_ must be unique across your entire bot because the dispatcher matches incoming interactions by exact _customId_ equality. The _style_ field maps to Discord's button styles and defaults to `'primary'` if omitted.

<CodeTabs>
  <Tab label="Component" language="typescript">
```typescript filename="src/components/buttons/confirm.button.ts"
import { Button } from '@spraxium/components';

@Button({
  customId: 'confirm_action',
  label: 'Confirm',
  style: 'success',
  emoji: 'âœ…',
})
export class ConfirmButton {}

````
  </Tab>
  <Tab label="Handler" language="typescript">
```typescript filename="src/components/buttons/confirm.handler.ts"
import { ButtonHandler, Ctx } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import { ConfirmButton } from './confirm.button';

@ButtonHandler(ConfirmButton)
export class ConfirmButtonHandler {
  async handle(@Ctx() interaction: ButtonInteraction): Promise<void> {
    await interaction.reply({ content: 'Action confirmed.', flags: 'Ephemeral' });
  }
}
````

The handler class must be decorated with _@ButtonHandler_ and pass the component class as its argument. This creates a metadata link that the dispatcher resolves during bootstrap. The _handle_ method receives parameters through decorators: _@Ctx()_ injects the raw _ButtonInteraction_, and _@FlowContext()_ injects the context object when present.

## Link buttons

Link buttons open a URL in the user's browser without firing any handler on the bot side. They are useful for directing users to documentation, dashboards, or external tools. Because Discord requires a different button style for links, the _@LinkButton_ decorator omits _customId_ and _style_ in favor of a _url_ field.

```typescript filename="src/components/buttons/docs-link.button.ts"
import { LinkButton } from '@spraxium/components';

@LinkButton({
  url: 'https://docs.example.com',
  label: 'View Documentation',
  emoji: 'ðŸ“–',
})
export class DocsLinkButton {}
```

Link buttons can be mixed with static buttons in the same action row. You pass all button classes to _ButtonService.build_ and the renderer produces the correct builder type for each one based on the metadata.

## Rendering with ButtonService

_ButtonService_ is the injectable service that transforms decorated classes into discord.js action rows. It provides two methods for different rendering scenarios. All methods read component metadata via reflection, so the service does not need explicit configuration beyond the decorated classes.

```typescript filename="src/commands/moderation.command-handler.ts"
import { Ctx, SlashCommandHandler } from '@spraxium/common';
import { ButtonService, ContextService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { ConfirmButton } from '../components/buttons/confirm.button';
import { CancelButton } from '../components/buttons/cancel.button';
import { DocsLinkButton } from '../components/buttons/docs-link.button';
import { ModerationCommand } from './moderation.command';

@SlashCommandHandler(ModerationCommand)
export class ModerationCommandHandler {
  constructor(
    private readonly buttons: ButtonService,
    private readonly context: ContextService,
  ) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const ctx = await this.context.create({ targetUserId: '123456' });
    const actionRow = this.buttons.rowWithContext(
      ctx,
      ConfirmButton,
      CancelButton,
    );
    const linkRow = this.buttons.build(DocsLinkButton);

    await interaction.reply({
      content: 'Review the moderation action below.',
      components: [actionRow, linkRow],
    });
  }
}
```

## Module registration

Only handler classes need to be registered, and they go in the _handlers_ array of your feature module. Component classes decorated with _@Button_ or _@LinkButton_ are metadata-only and are never added to any module. The dispatcher reads their customId and configuration directly from the class reference stored inside each _@ButtonHandler_ decorator, with no DI instantiation required.

```typescript filename="src/modules/moderation/moderation.module.ts"
import { Module } from '@spraxium/common';
import { ConfirmButtonHandler } from './components/confirm.handler';
import { CancelButtonHandler } from './components/cancel.handler';
import { UserBanButtonHandler } from './components/user-ban.handler';

@Module({
  handlers: [ConfirmButtonHandler, CancelButtonHandler, UserBanButtonHandler],
})
export class ModerationModule {}
```

## Dynamic buttons

Static buttons use a fixed _customId_ known at definition time. Dynamic buttons invert this: the button's label, style, and the data it carries are computed per render from an arbitrary payload object. The custom ID is generated automatically by the framework and encodes a reference to the stored payload. The handler retrieves the original payload from the store when the button is clicked.

The dynamic button system has three parts: the _@DynamicButton_ class that defines the component and its rendering logic, the _@DynamicButtonHandler_ class that handles the click, and the payload store that bridges the two.

### Defining a dynamic button

A dynamic button class is decorated with _@DynamicButton_ and must expose a static `render(item)` method that returns a `ButtonRenderConfig`. The _baseId_ in the config is the prefix used when matching incoming interactions, and the framework appends the payload reference automatically. The _payloadTtl_ is an optional TTL in seconds; payloads expire after this duration and any click after expiry will not reach the handler (defaults to 600 seconds, 10 minutes).

<CodeTabs>
  <Tab label="Component" language="typescript">
```typescript filename="src/components/buttons/book-buy.button.ts"
import { DynamicButton } from '@spraxium/components';
import type { ButtonRenderConfig } from '@spraxium/components';

interface Book {
  id: string;
  title: string;
}

@DynamicButton({ baseId: 'buy-book', payloadTtl: 300 })
export class BuyBookButton {
  static render(book: Book): ButtonRenderConfig {
    return {
      label: `Buy "${book.title}"`,
      style: 'success',
    };
  }
}
```
  </Tab>
  <Tab label="Handler" language="typescript">
```typescript filename="src/components/buttons/book-buy.handler.ts"
import { DynamicButtonHandler, Ctx, ButtonPayload, PayloadRef } from '@spraxium/components';
import type { ButtonInteraction } from 'discord.js';
import type { PayloadHandle } from '@spraxium/components';
import { BuyBookButton } from './book-buy.button';

interface Book {
  id: string;
  title: string;
}

@DynamicButtonHandler(BuyBookButton)
export class BuyBookButtonHandler {
  async handle(
    @Ctx() interaction: ButtonInteraction,
    @ButtonPayload() book: Book,
    @PayloadRef() ref: PayloadHandle,
  ): Promise<void> {
    await ref.consume(); // one-shot; prevent double purchase
    await this.orders.create(book.id, interaction.user.id);
    await interaction.reply({ content: `Purchased "${book.title}"!`, flags: 'Ephemeral' });
  }
}
```

### Rendering a dynamic button

To render a single dynamic button into an action row, call `ButtonService.build` passing the component class and the payload object. The service calls `render(item)`, stores the payload in the TTL-bounded store, and returns an _ActionRowBuilder_ with the generated custom ID embedded.

```typescript filename="src/commands/shop.command-handler.ts"
import { SlashCommandHandler, Ctx } from '@spraxium/common';
import { ButtonService } from '@spraxium/components';
import type { ChatInputCommandInteraction } from 'discord.js';
import { BuyBookButton } from '../components/buttons/book-buy.button';
import { ShopCommand } from './shop.command';

@SlashCommandHandler(ShopCommand)
export class ShopCommandHandler {
  constructor(private readonly buttons: ButtonService) {}

  async handle(@Ctx() interaction: ChatInputCommandInteraction): Promise<void> {
    const book = await this.catalog.getBook('978-0-7432-7356-5');
    const row = this.buttons.build(BuyBookButton, book);

    await interaction.reply({
      content: `Found **${book.title}**`,
      components: [row],
    });
  }
}
```

To combine multiple dynamic buttons of different types into the same row, use `ButtonService.buildMixedRow`. It accepts an array of `{ button, items }` entries and returns a single `ActionRowBuilder` alongside a flat array of all payload refs - one per store-encoded button, in declaration order. Inline-encoded buttons produce no ref and are omitted from the refs array.

```typescript filename="src/commands/open-ticket.command-handler.ts"
import { Ctx, SlashCommandHandler, SlashStringOption } from '@spraxium/common';
import { ButtonService } from '@spraxium/components';
import { type ChatInputCommandInteraction, MessageFlags } from 'discord.js';
import { OpenTicketCommand } from '../commands/open-ticket.command';
import { AssignTicketButton } from '../components/assign-ticket-button.component';
import { CloseTicketButton } from '../components/close-ticket-button.component';
import { TicketsRepository } from '../tickets.repository';

@SlashCommandHandler(OpenTicketCommand)
export class OpenTicketHandler {
  constructor(
    private readonly buttons: ButtonService,
    private readonly tickets: TicketsRepository,
  ) {}

  async handle(
    @Ctx() interaction: ChatInputCommandInteraction,
    @SlashStringOption('subject') subject: string,
  ): Promise<void> {
    const ticket = await this.tickets.create({
      subject,
      openedBy: interaction.user.id,
    });

    // buildMixedRow renders both buttons into one row and collects all store refs.
    // AssignTicketButton is store-encoded (payload persisted, ref tracked for revocation).
    // CloseTicketButton is inline-encoded (ticket id encoded in the customId, no ref).
    const [row, refs] = await this.buttons.buildMixedRow([
      { button: AssignTicketButton, items: [ticket] },
      { button: CloseTicketButton, items: [ticket] },
    ]);

    // Persist each ref so it can be revoked when the ticket is closed externally.
    await Promise.all(refs.map((ref) => this.tickets.addAssignRef(ticket.id, ref)));

    await interaction.reply({
      content: [
        `## 🎫 Ticket \`${ticket.id}\``,
        `**Subject:** ${ticket.subject}`,
        `**Opened by:** <@${ticket.openedBy}>`,
      ].join('\n'),
      components: [row],
      flags: MessageFlags.Ephemeral,
    });
  }
}
```

### Module registration

Dynamic button handlers follow the same registration rules as static button handlers. Register only the handler class in the _handlers_ array of your module. The component class decorated with _@DynamicButton_ is metadata-only and does not need to appear in any module.

```typescript filename="src/modules/shop/shop.module.ts"
import { Module } from '@spraxium/common';
import { BuyBookButtonHandler } from './components/book-buy.handler';

@Module({
  handlers: [BuyBookButtonHandler],
})
export class ShopModule {}
```

<Callout tone="tip">
  _@DynamicStringSelect_ works the same way for select menus: define a class
  with *@DynamicStringSelect*, expose a static render(items) method returning
  a SelectRenderConfig, and write a handler with *@DynamicSelectHandler*. Use
  *@SelectPayload()* instead of *@ButtonPayload()* to inject the stored payload.
</Callout>

### Inline params encoding

By default, dynamic buttons store their payload in a TTL-bounded server-side store and embed only an opaque reference in the custom ID. This is the right choice for large or complex objects.

For small, primitive data - like a single database record ID - you can use `encoding: 'inline'` instead. The framework encodes the params directly into the custom ID string, removing any dependency on the payload store and the TTL entirely. The data lives in the Discord message for as long as the message exists.

<Callout tone="warning">
  Discord enforces a hard limit of **100 characters** on custom IDs. The framework
  measures the encoded string at render time and throws
  `DynamicButtonInlinePayloadTooLargeError` if the result would exceed this limit.
  Keep inline params small: one or two short IDs or flags. Use store-based encoding
  for anything larger.
</Callout>

Notice that `@ButtonParams()` replaces `@ButtonPayload()` for inline-encoded buttons. Using `@ButtonPayload()` or `@PayloadRef()` on an inline handler causes a bootstrap error. The type of `params` is inferred from the `params` field returned by `render()`, so TypeScript knows the shape without any manual casting.

The encoded custom ID for the example above looks like `approve-suggestion~id=42`. Values are URL-encoded to handle special characters. Numbers and booleans are cast back to their original types when decoded.

### Revoking payloads externally

When a dynamic button payload lives in the store, the handler can consume it with `ref.consume()` after handling the click. But some flows require revoking a payload before any click happens - for example, closing a ticket via a slash command should immediately invalidate the approve/reject buttons in the admin channel.

Inject `ButtonPayloadService` to revoke one or more payload refs from any service, command handler, or listener.

**Storing refs at render time**

`ButtonService.buildMixedRow` returns a tuple `[ActionRowBuilder, string[]]`. The refs array contains one entry per store-encoded button in declaration order. Inline-encoded buttons produce no ref. Store each ref in your database so it can be revoked later:

```typescript filename="src/repositories/tickets.repository.ts"
interface TicketRecord {
  id: string;
  subject: string;
  openedBy: string;
  assignRefs: string[]; // payload refs for all store-encoded buttons
  status: 'open' | 'closed';
}

export class TicketsRepository {
  async create(data: Pick<TicketRecord, 'subject' | 'openedBy'>): Promise<TicketRecord> {
    // INSERT INTO tickets (...)
    return { id: 'ticket-uuid', assignRefs: [], status: 'open', ...data };
  }

  async addAssignRef(ticketId: string, ref: string): Promise<void> {
    // UPDATE tickets SET assign_refs = JSON_ARRAY_APPEND(assign_refs, '$', ?) WHERE id = ?
  }

  async findOpenById(ticketId: string): Promise<TicketRecord | null> {
    // SELECT ... WHERE id = ? AND status = 'open'
    return null;
  }
}
```

Then, when the ticket is closed from outside a handler, load the record and revoke all refs:

```typescript filename="src/commands/close-ticket.command-handler.ts"
const ticket = await this.tickets.findOpenById(ticketId);

if (ticket?.assignRefs.length) {
```

**Revoking when the flow ends externally**

```typescript filename="src/commands/close-ticket.command-handler.ts"
import { SlashCommandHandler, Ctx, SlashStringOption } from '@spraxium/common';
import { ButtonPayloadService } from '@spraxium/components';
import { type ChatInputCommandInteraction, MessageFlags } from 'discord.js';
import { CloseTicketCommand } from '../commands/close-ticket.command';
import { TicketsRepository } from '../tickets.repository';

@SlashCommandHandler(CloseTicketCommand)
export class CloseTicketHandler {
  constructor(
    private readonly payloads: ButtonPayloadService,
    private readonly tickets: TicketsRepository,
  ) {}

  async handle(
    @Ctx() interaction: ChatInputCommandInteraction,
    @SlashStringOption('ticket-id') ticketId: string,
  ): Promise<void> {
    const ticket = await this.tickets.findOpenById(ticketId);

    if (!ticket) {
      return interaction.reply({ content: 'Ticket not found or already closed.', flags: MessageFlags.Ephemeral });
    }

    // Revoke all store-encoded button refs - any subsequent click will receive
    // the configured expired message instead of reaching the handler.
    if (ticket.assignRefs.length) {
      await this.payloads.revokeMany(ticket.assignRefs);
    }

    await this.tickets.close(ticketId);
    await interaction.reply({ content: `Ticket \`${ticketId}\` closed.`, flags: MessageFlags.Ephemeral });
  }
}
```
