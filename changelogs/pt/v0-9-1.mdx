O Spraxium 0.9.1 adiciona o comando `spraxium use` para trocar a versão do framework em um bot existente. Junto dessa versão, abrimos o canal `next` com a `1.0.0-dev.1`, a primeira prévia do trabalho na 1.0. Assim, você pode experimentar as mudanças em um projeto e voltar para a versão estável depois.

## Troque de versão pela pasta do bot

Rode o comando na pasta do projeto. O dry run mostra quais pacotes seriam alterados, para que você confira a troca antes de instalar.

```sh
spraxium use next --dry-run
spraxium use next
spraxium use stable
```

A CLI verifica se a versão escolhida existe no npm para cada pacote Spraxium declarado pelo bot. Em seguida, fixa todos na mesma versão e atualiza o lockfile com o gerenciador do projeto. Se a instalação falhar ou resolver outra versão, ela recupera os arquivos anteriores e tenta reinstalar aquelas dependências.

Também dá para passar uma versão exata, como `spraxium use 1.0.0-dev.1`, quando você precisa reproduzir um bug. Rodar `use next` novamente instala a prévia disponível naquele momento, enquanto `use stable` acompanha a tag `latest` do npm. [Guia de troca de versão](/pt/guide/cli-use).

## Saiba qual build está rodando

A saída de inicialização passa a identificar as builds de desenvolvimento, inclusive quando o bot inicia sem acesso à internet. Os avisos de atualização acompanham o canal instalado. Um bot estável recebe novidades estáveis, e uma prévia pode avisar sobre uma build mais recente da mesma série. Quando há uma versão estável mais nova, esse aviso tem prioridade. A consulta acontece em segundo plano e guarda o resultado por 24 horas.

A primeira prévia inclui uma entrada CommonJS para o Signal Client, armazenamento compartilhado de nonces no Redis para bots com várias instâncias e ajustes na descoberta e na execução de tarefas agendadas com Redis. Se você usa esses recursos, vale testar a inicialização e os reinícios habituais do bot e informar a versão instalada ao relatar algum problema.
