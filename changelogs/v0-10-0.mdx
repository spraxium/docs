A dashboard often needs information that only the bot has, like the server where a ticket was opened or the member count Discord reported. In 0.10.0 a backend can ask a Spraxium bot for that information through a named RPC method. The backend still takes care of its URLs, sessions, and user permissions. The bot keeps its Discord connection and the code that reads or changes something in a guild. Each RPC call carries a service credential and a deadline, and a bot with native sharding can route a guild call through its parent to the child that owns that guild.

Install `@spraxium/rpc` in the bot and `@spraxium/rpc-client` in the backend. The guides walk through a first call, then build a guild-stats route you can try in NestJS, Express, Hono, Fastify, Koa, or Node. The examples are written in TypeScript, including the CommonJS client. [Make your first RPC call](/en/guide/rpc-quickstart) · [Wire the NestJS module and service](/en/guide/rpc-nestjs)

## Why the framework is moving on from HTTP

The legacy `@spraxium/http` package let a bot provide web routes as well as Discord features. Maintaining the web runtime meant keeping a second copy of routing, middleware, CORS, validation and HTTP error handling up to date. Many projects were already running NestJS, Express or another server for those jobs. Changes in the web layer took time away from the part unique to Spraxium: making a backend request reach the right bot code, including when the bot runs across shards.

`@spraxium/http` is deprecated in 0.10.0. Existing bots can migrate one route at a time. Start with a read, keep its public URL and use the migration checklist to compare the old response with the new path. After the last route moves, remove the old runtime and its configuration. [Migration walkthrough](/en/guide/rpc-http-migration) · [Agent skill for the migration on GitHub](https://github.com/spraxium/rpc/blob/main/SKILL.md)

The release also updates discord.js to 14.28.1 and refreshes Hono used by the legacy HTTP package.

## Documentation for the version you run

The current guides are generated from the latest docs release and the sidebar keeps a copy of 0.9.0 available for bots that haven't upgraded. Switching versions keeps the same topic when it exists in both. Search follows the selected version. The 0.10.0 docs explain how to configure the RPC gateway, how a request reaches a handler, and what to test while moving a real API route. There are also examples of splitting environment validators by feature and a guide to testing a Spraxium preview without losing a known-good install. [Environment structure](/en/guide/env-project-structure) · [Switch versions](/en/guide/cli-use)

The review also corrected the Node.js prerequisites, the examples for configuring text commands and replying to errors, and the reference for environment validation. The examples for select menus now use the same decorators your bot imports from the current packages.

## Skills for coding agents

If your agent is adding a slash command, configuring scheduling, or working on a bot feature, you can give it the corresponding `SKILL.md`. The general skill points agents to the official examples and tells them how to match the repo structure and version before changing code. Every card opens its full guide in the catalog and links to a named file. Agents can use a JSON index or the topic resolver to get to the right file. The catalog is built from the docs repository, so a content update reaches the site on the next deploy. [Browse skills](/en/skills) · [Machine-readable index](/skills/index.json)

## Changes on the website

The homepage has a redesigned package list with install commands and a description for each package, a FAQ, a framework comparison and a chart using a ticket and moderation bot as the scenario. ScrollTrigger handles the homepage entrances and chart reveal, with reduced-motion support. The articles and release notes use simpler reading layouts. Docs keep the navigation and contents at the edges on desktop. On mobile the main menu opens at the top and scrolling the docs sidebar stays inside it. Localized pages also guard against an issue where a page could show raw React data instead of HTML.

On the homepage, the skills demo appears above the package list and cards enter one at a time as you scroll. Switching languages preserves the theme, and you can keep scrolling while the pointer is over the chat. The skills reader wraps long lines and uses one background for the guide and its header. Documentation callouts use dashed borders, with blue for informational notes.
