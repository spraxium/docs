The main addition in 0.10.0 is Spraxium RPC. You can now call a method in your bot from a backend and use the response in a dashboard, script, or another service. This gives projects that run a bot alongside a web app a way to share the bot's features while keeping the Discord connection in one place.

The bot uses `@spraxium/rpc` to handle calls, and the backend uses `@spraxium/rpc-client` to make them. Calls have types, authentication, and a time limit. When a bot uses native sharding, Spraxium sends a guild request to the shard responsible for that server. The setup guides cover a first call and integrations with backends such as NestJS and Express. [Get started with RPC](/en/guide/rpc-quickstart).

## Why we're moving away from HTTP

With `@spraxium/http`, we were maintaining a web server inside the bot, including routes, middleware, CORS, validation, and HTTP errors. Many projects already had a backend doing that work. Supporting both meant maintaining similar features in two places and spending time on problems that web frameworks already handle.

RPC lets us focus on the connection between the backend and the bot. Your web framework manages the public API, login, and user permissions, while Spraxium handles calls to bot methods and routes them between shards. It also means you can keep the backend framework your project already uses.

As part of this change, `@spraxium/http` is deprecated. Existing projects can migrate one route at a time and keep the URLs their dashboards already call. We wrote a guide that follows the move from an HTTP route to an RPC call, including the changes on both sides. [Read the migration guide](/en/guide/rpc-http-migration).

## Docs that follow your framework version

The documentation now has separate guides for each supported version. You can read the instructions for the version installed in your bot, then switch when you're ready to upgrade. The latest docs open by default, and the sidebar keeps the 0.9.0 archive available.

We also reviewed the existing guides, updated examples, and removed instructions that no longer matched the framework. Some features needed more explanation, so the RPC tutorials now follow a call from the backend to the bot, and the environment guides show how to organize validators as a project grows. You can follow the setup through the guides even if you're using the feature for the first time.

## Skills for coding agents

There's a new skills catalog for working with Spraxium through coding agents. Each skill gives the agent instructions for a particular task, with examples and links to the relevant docs. The catalog covers project setup, commands, components, guards, scheduling, logging, and other parts of the framework.

You can read a guide on the site and download its file for your agent. The general skill helps it find the right topic, check the installed version, and follow the structure of the official examples. There's also a skill for migrating from HTTP to RPC, so the agent has the steps and context for that change. [Browse the skills](/en/skills).

## Changes on the website

We redesigned several parts of the site and improved how you move between guides, packages, articles, and release notes. The layout is more consistent, the menus are easier to use, and the docs keep your place in the sidebar when you open another page. Together, these changes make the site feel more organized and help you get back to what you were reading with less interruption.
