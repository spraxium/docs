Spraxium 0.9.1 adds `spraxium use` to change the framework version in an existing bot. Alongside this release, we opened the `next` channel with `1.0.0-dev.1`, the first preview from the 1.0 development branch. You can try that work in a project and return to the stable version afterward.

## Changing versions from your project

Run the command from the bot's directory. The dry run shows which packages would change, so you can review the switch before installing anything.

```sh
spraxium use next --dry-run
spraxium use next
spraxium use stable
```

The CLI checks whether npm has the requested version for every Spraxium package declared by the bot. It then pins those packages to the same version and updates the lockfile using your project's package manager. If installation fails or resolves a different version, it restores the previous files and tries to reinstall those dependencies.

You can also pass an exact version, such as `spraxium use 1.0.0-dev.1`, when you need to reproduce a bug. Running `use next` again installs the preview available at that time, while `use stable` follows npm's `latest` tag. [Version switching guide](/en/guide/cli-use).

## Knowing which build is running

The startup output now identifies development builds, including when the bot starts offline. Update notices follow the installed channel, so a stable bot gets stable updates and a preview can report a newer build in the same series. A newer stable release takes priority when one becomes available. The check runs in the background and caches its result for 24 hours.

The first preview includes a CommonJS entry point for Signal Client, shared Redis nonce storage for bots with multiple instances, and changes to scheduled job discovery and Redis leases. If you use those features, try your normal startup and restart routine with the preview and include the installed version in any bug report.
